<Title>v1.42.0</Title>

<Heading>Ломающие изменения</Heading>

**MaskedField**

- Тип `maskedInputProps.ref` изменён с `React.RefObject<HTMLInputElement>` на `React.RefObject<HTMLDivElement>`. Поведение прежнее: этот ref всегда указывал на корневой `<div>` обёртки `FormFieldMaskedInput` (`forwardRef<HTMLDivElement>`), а не на поле ввода — прежний тип вводил в заблуждение. Миграция: код, который читает `ref.current` как `HTMLInputElement`, нужно перевести на `maskedInputProps.forwardedRef` — это единственная ссылка на элемент `<input>`; для ссылки на обёртку смените тип на `HTMLDivElement`. Передача существующего `useRef<HTMLInputElement>(null)` в `maskedInputProps.ref` по-прежнему компилируется (`RefObject<HTMLInputElement>` присваивается в `RefObject<HTMLDivElement>`), но `ref.current` в рантайме, как и раньше, будет `HTMLDivElement`.

<Heading>Изменения</Heading>

**AlertProcess**

- Исправлено: `className`, переданный в `AlertProcess.Spoiler`, полностью затирал собственные классы элемента — `{...rest}` расходился после `className`, поэтому вместе с пользовательским классом пропадали `expandableContent` / `expanded` и ломалась анимация раскрытия. Теперь класс мерджится через `clsx`, как в остальных компонентах.
- Исправлено: `AlertProcess.Spoiler` не пробрасывал `ref` — компонент был объявлен как `React.FC`. Теперь это `forwardRef`, ref указывает на элемент раскрываемого контента, то есть на тот же элемент, что получает `...rest`.
- Изменено: из разметки `AlertProcess.Spoiler` убрана пустая обёртка-`<div>` — раскрываемый контент и кнопка раскрытия теперь соседние элементы, а корневым элементом компонента стал элемент контента. Обёртка не имела ни классов, ни стилей и не участвовала в позиционировании кнопки (та позиционируется от корня `AlertProcess`), поэтому визуально ничего не изменилось. Если ваш код опирался на лишний уровень вложенности в CSS-селекторах или в поиске по DOM — селекторы нужно поправить.
- Добавлено: на кнопке раскрытия `AlertProcess.Spoiler` выставляется `aria-expanded` — состояние раскрытия теперь доступно скринридерам. `aria-controls` и доступное имя кнопки по-прежнему не выставляются: первому нужен стабильный `id`, второму — новый prop для проброса `aria-label`.
- AI-рефакторинг: JSDoc на всех props с указанием значений по умолчанию, в `IAlertProcessProps` добавлен явный `children`, `renderIcon` приведён к `||` вместо тернарника (как в `AlertContext`), убрано дублирующее присваивание `AlertProcess.Spoiler` после `Object.assign`, удалена ссылка на несуществующий CSS-класс `styles.spoiler` (в сборке она давала `undefined`, визуально ничего не меняется), из LESS удалено мёртвое правило `.alertTypeFeature .themeIcon { padding-top: 0 }`. Unit-тесты разбиты на `AlertProcess.test.tsx` и `AlertProcessSpoiler.test.tsx` и расширены с 11 до 37 кейсов, stories переведены на modern pattern, создан `AlertProcess-ai.md`. Публичный API не изменён (props, их типы, значения enum, barrel-экспорты — как были), визуальное отображение компонента не изменилось.

**ComposedKeyDownListener**

- Исправлено: смена набора горячих клавиш перемонтировала содержимое. Слушатели рендерятся соседями к `children`, а не оборачивают их — раньше глубина вложенности `KeyDownListener` равнялась длине `keyDownListeners`, поэтому при её изменении между рендерами `children` пересоздавались вместе с DOM-узлами и теряли введённые значения инпутов, фокус и текущие анимации. Теперь структура React-дерева не зависит от длины и порядка массива, содержимое остаётся смонтированным.
- Публичный API не изменён: props и их типы, `IComposedKeyDownListenerProps`, barrel-экспорты — как были. Собственной разметки компонент как не рендерил, так и не рендерит, поэтому итоговый DOM не меняется. `onMatch` по-прежнему вызываются в порядке элементов `keyDownListeners`.
- Изменился относительный порядок подписок на `window`: слушатели композитора теперь монтируются раньше `children`, а не после них. Если внутри `children` есть собственный глобальный `keydown`-обработчик той же клавиши, `onMatch` сработает раньше него, а не позже — важно для кода, который полагается на этот порядок или на `stopImmediatePropagation`.

**LoaderSmall**

- AI-рефакторинг: JSDoc на компоненте, props и значениях `ELoaderSmallTheme`, порядок импортов приведён к codestyle, константы-маппинги переименованы в `THEME_TO_CLASS_NAME_MAP` / `SIZE_TO_CLASS_NAME_MAP` (внутренние, не экспортировались), в стилях объединено дублирующееся объявление анимации точек — сама анимация задана один раз на `.dot`, у точек осталась только `animation-delay`, unit-тесты расширены с 3 до 6 кейсов, создан `LoaderSmall-ai.md`. Экспортируемый, но неиспользуемый компонентом enum `ELoaderSmallSize` сохранён и помечен в документации как legacy — размер задаётся `EComponentSize`. В stories `controls: { disable: true }` перенесён на верхний уровень `parameters` — внутри `docs` он не применялся. Публичный API и поведение не изменены (props, значения enum, barrel-экспорты, DOM-разметка, `role="status"`, токены — как были).

**MaskedField**

- AI-рефакторинг: расширены JSDoc на компоненте и на prop `maskedInputProps` (перечислены обязательные `mask` / `value`, `placeholderMask` и `forwardedRef` для ссылки на input), добавлены unit-тесты (13 кейсов: применение маски к значению, вызов `onChange` с отформатированным значением, отображение плейсхолдера маски, проброс ref, статусы, слоты), stories мигрированы на modern pattern с примерами в `stories/MaskedField/examples/` и добавлены стори `WithPlaceholderMask`, `PassRefToInput`, `VisualTests`, создан `MaskedField-ai.md`. DOM и визуальное поведение не изменены; в публичном API поменялся только тип `maskedInputProps.ref` (см. «Ломающие изменения») — состав props, barrel-экспорты и `forwardRef` как были.

**MobileView**

- AI-рефакторинг: у `MobileView` появился `displayName`, у `useMobileView` — явный тип возвращаемого значения `boolean`, уточнён JSDoc компонента и хука. Добавлены unit-тесты (15 кейсов на компонент и хук) и stories по modern pattern, создан `MobileView-ai.md`. Публичный API и поведение не изменены: props `children` и `fallback`, сигнатура `useMobileView`, barrel-экспорты и граница мобильной ширины (`EScreenWidth.SM_MAX`, `max-width: 767px`) — как были.
