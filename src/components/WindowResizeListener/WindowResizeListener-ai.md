# WindowResizeListener

## Назначение

Сервисный headless-компонент. Пока смонтирован, слушает событие `resize` на
`window` и вызывает `onResize`, но не чаще, чем раз в `throttleDelay`
миллисекунд. Собственной разметки не рендерит: `children` выводятся как есть,
без обёртки; без `children` не рендерит ничего.

Используй когда: при изменении размеров окна нужно выполнить императивное
действие — пересчитать размеры/отступы по замеренному DOM, перепозиционировать
оверлей, сбросить кэш измерений.

Не используй когда:
- Нужно отрендерить **другое дерево** компонентов на другой ширине — для этого
  есть `MediaWidth` / `MobileView`, они слушают `MediaQueryList`, а не поток
  событий `resize`.
- Нужно булево значение «широкий/узкий экран» для props или условной разметки —
  используй `useMatchMedia` (`src/components/MediaWidth/useMatchMedia.ts`) или
  `useMobileView`.
- Отслеживать нужно размер конкретного элемента, а не окна — окно может не
  меняться, а элемент — да (открылась панель, изменился контент). Для этого в
  библиотеке используется `useResizeDetector` из `react-resize-detector`
  (пример — `LightBoxContent`).
- Разница чисто визуальная (отступы, шрифт, раскладка) — это дешевле решается
  медиа-запросом в `*.module.less`, без JS-обработчика на каждое событие.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `onResize` | `(event: UIEvent) => void` | Вызывается на `resize` окна. Получает нативный `UIEvent` (не React SyntheticEvent). Полезной нагрузки в событии нет — актуальные размеры читаются из `window.innerWidth` / `innerHeight` или замером DOM |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `throttleDelay` | `number` | `100` | Минимальный интервал между вызовами `onResize`, в миллисекундах |
| `children` | `React.ReactNode` | — | Рендерится как есть. Компонент не оборачивает содержимое и никак на него не влияет — вложение нужно только для читаемости кода |

### Особенности поведения

- Слушатель навешивается в `useEffect`, поэтому `window` не трогается во время
  рендера — компонент **SSR-safe** (в отличие от семейства `MediaWidth`, которое
  вызывает `window.matchMedia` на первом рендере).
- Троттлинг — `throttle` из `lodash-es` с настройками по умолчанию:
  **leading + trailing**. Первое событие серии обрабатывается синхронно, все
  последующие внутри окна схлопываются в один отложенный вызов в конце окна.
  Одиночное событие даёт ровно один вызов; если внутри окна пришли ещё события,
  в конце окна добавляется trailing-вызов.
- **Обработчик и задержка входят в зависимости эффекта.** При смене ссылки
  `onResize` или значения `throttleDelay` слушатель снимается и навешивается
  заново, а троттлинг начинается с чистого листа (новое leading-окно). Если
  передать инлайновую стрелку, переподписка будет происходить на **каждый
  рендер**, и троттлинг фактически перестанет ограничивать частоту вызовов.
  Оборачивай обработчик в `useCallback` (или храни его вне компонента).
- При размонтировании слушатель снимается, а отложенный trailing-вызов
  отменяется через `cancel()` — `removeEventListener` сам по себе его
  не отменяет, и колбэк сработал бы уже после размонтирования.
- Компонент не вызывает `preventDefault` / `stopPropagation` (событие `resize`
  не отменяемо) и не подмешивает в `onResize` собственные данные о размерах.
- Несколько смонтированных `WindowResizeListener` работают независимо, каждый со
  своим окном троттлинга.

## Инварианты

- **Без `forwardRef` — осознанное исключение** из общего правила библиотеки:
  компонент не рендерит собственный host-элемент, форвардить `ref` некуда. Не
  добавлять и не убирать без отдельного решения.
- **Имена и типы props `children`, `onResize`, `throttleDelay`** и значение по
  умолчанию `throttleDelay = 100` — публичное API, не менять. Интерфейс
  `IWindowResizeListenerProps` экспортируется из barrel — переименование будет
  breaking change.
- **`return children ?? null`** — falsy-`children` (`0`, `""`) осознанно
  рендерятся; `??`, а не `||` (у соседнего `KeyDownListener` обратная
  договорённость — там `||`). Возврат `null` вместо `undefined` нужен для React
  17: там компонент, вернувший `undefined`, роняет рендер.
- **Зависимости эффекта `[onResize, throttleDelay]`** — не «оптимизировать»
  переносом обработчика в `ref`: сейчас смена обработчика сбрасывает окно
  троттлинга, и это наблюдаемое поведение у потребителей.
- **`throttledResize.cancel()` в cleanup** — не удалять: без него отложенный вызов
  срабатывает после размонтирования (тест `cancels the pending trailing call on
  unmount`).
- Реализация остаётся React 17-совместимой (без `useId`,
  `useSyncExternalStore` и прочих React 18-only API): код синхронизируется
  в `release-0`.

## Accessibility

- Собственной ARIA-семантики нет — компонент прозрачен для accessibility-дерева
  и не рендерит фокусируемых элементов.
- `resize` окна возникает и при зуме страницы, и при появлении экранной
  клавиатуры на мобильных. Обработчик не должен перебрасывать фокус или
  сбрасывать состояние формы — для пользователя, увеличившего масштаб, это
  выглядит как потеря контекста.

## Связанные компоненты

- `MediaWidth` (`src/components/MediaWidth/`) — альтернатива для декларативного
  случая: рендерит одну из двух веток по медиа-запросу, а не даёт колбэк на поток
  событий. Там же `useMatchMedia` (булево значение для условной разметки) и
  `MobileView` (частный случай мобильной границы). Правило выбора: нужно
  **что-то посчитать/сделать** на ресайз — `WindowResizeListener`; нужно
  **что-то показать** на определённой ширине — `MediaWidth`.
- `KeyDownListener` (`src/components/KeyDownListener/`) — headless-слушатель того
  же покроя, но для `keydown` на `window`. Похожий контракт по `children` (рендер
  как есть, без обёртки); отличие — обработка falsy-`children`, см. «Инварианты».

### Потребители внутри библиотеки

- `LightBoxContent` (`src/components/LightBox/LightBoxContent.tsx`) — пересчёт
  верхнего отступа контента при изменении размеров окна. Обработчик
  (`updateStyleWithTimeout`) обёрнут в `useCallback`, поэтому переподписки на
  каждый рендер не происходит. Слушатель размеров самого контента там сделан
  отдельно, через `useResizeDetector`.

В unit-тестах потребителей компонент удобно мокать целиком — как в
`src/components/LightBox/__tests__/LightBoxContent.test.tsx`.
