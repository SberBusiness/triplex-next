# UnorderedListExtended

## Назначение

Маркированный список с составным JSX-API: элементы собираются вручную через `UnorderedListExtended.Item`,
маркер добавляется явно первым потомком элемента — `UnorderedListExtended.Item.Marker`.

Используй когда: элемент списка — композиция из нескольких узлов (ссылка, бейдж, вложенный блок),
маркеры разнородны внутри одного списка, или часть элементов должна остаться без маркера.

Не используй когда:
- Список строится из данных и каждому элементу достаточно текста и одного маркера — это `UnorderedList`
  с массивом `items`, он сам разворачивает элементы и сам добавляет обёртку маркера.
- Нужен нумерованный список — используй `OrderedList`.
- Нужен список записей с действиями, выделением, сортировкой — это `List` и его семейство,
  а не типографический маркированный список.

## Варианты и props

### Обязательные props

Обязательных props нет ни у одной части составного API.

### Собственные props

Собственных props нет ни у списка, ни у элемента, ни у обёртки маркера — все три интерфейса
пустые и наследуют чужие:

| Компонент | Интерфейс | Что принимает |
|---|---|---|
| `UnorderedListExtended` | `IUnorderedListExtendedProps` | Стандартные атрибуты `<ul>` |
| `UnorderedListExtended.Item` | `IUnorderedListExtendedItemProps` | Типографику `Text` без `tag` плюс стандартные атрибуты `<li>` |
| `UnorderedListExtended.Item.Marker` | `IUnorderedListExtendedItemMarkerProps` | Стандартные атрибуты `<span>` |

Особенности, которые не видны из типов:

- **Размер текста элемента** по умолчанию — `ETextSize.B3`; это единственный дефолт во всём компоненте.
- **Маркер опционален.** Элемент без `UnorderedListExtended.Item.Marker` рендерится вообще без обёртки
  маркера — текст начинается от левого края. Это ключевое отличие от `UnorderedList`, где обёртка
  добавляется всегда.
- **Маркер-точка рисуется только при `children === undefined`.** `<Marker />` даёт точку,
  а `<Marker>{null}</Marker>` или `<Marker>{false}</Marker>` — пустую обёртку. Проверка строгая
  (`children === undefined`), поэтому условный маркер вида `{cond && <Icon />}` внутри `Marker`
  при `cond === false` не откатится на точку.
- **`tag` элемента исключён типом** (`Omit<TTextProps<"li">, "tag">`): элемент всегда `<li>`.

## Дизайн-токены

Собственных CSS-переменных нет. Цвет текста и маркера приходит из типографики `Text` через prop `type`
элемента: точка залита `currentcolor`, поэтому меняется вместе с цветом текста.

Стили — только layout: у списка сброс `margin`/`padding`/`list-style`, у элемента `display: flex`
с `align-items: flex-start` и `gap: 4px` (плюс `margin-top: 8px` между соседями), у обёртки маркера
центрирование содержимого.

Обёртка маркера тянется на высоту строки элемента (`min-height: 1lh` с фолбэком `20px` для браузеров
без единицы `lh`), поэтому маркер центрируется по первой строке при любом `size`. Высота — минимум,
а не фиксированное значение: маркер выше строки (иконка 20px при `B4`) не обрезается.

## Инварианты

- **`forwardRef`** на всех трёх компонентах — не убирать. Ref указывает на корневой элемент
  (`<ul>`, `<li>`, `<span>` соответственно) — тот же, что получает `className`, `...rest` и `data-tx`.
- **Составной API через `Object.assign`**: `UnorderedListExtended.Item` и `UnorderedListExtended.Item.Marker` —
  публичные точки входа. Разбиение на отдельные именованные экспорты сломает контракт потребителей.
- **Маркер-обёртка не добавляется автоматически.** Список не оборачивает и не инспектирует своих детей;
  добавление неявного маркера сломает элементы, задуманные без него.
- **Строгая проверка `children === undefined`** в маркере — не заменять на проверку на falsy:
  `<Marker>{null}</Marker>` обязан давать пустую обёртку, а не точку.
- **Вертикальное выравнивание маркера** задаётся высотой обёртки, а не фиксированными вертикальными
  отступами точки: отступы под конкретную строку (`20px` для `B2`/`B3`) сместят маркер на `B1` и `B4`.
- **`displayName`**: `"UnorderedListExtended"`, `"UnorderedListExtendedItem"`,
  `"UnorderedListExtendedItemMarker"` — не менять.
- **Barrel `index.ts`** экспортирует типы и `UnorderedListExtended`; субкомпоненты наружу отдельно
  не экспортируются — только через статические свойства.

## Accessibility

- Семантика штатная: корневой элемент — `<ul>` (`role="list"`), элементы — `<li>` (`role="listitem"`).
  Дополнительных ARIA-атрибутов компонент не выставляет.
- Маркер лежит в обычном `<span>` и **не** скрыт от скринридеров. Текстовый маркер (например, `"1."`)
  будет озвучен; для декоративного маркера-иконки передавай `aria-hidden="true"` — либо на сам
  `UnorderedListExtended.Item.Marker`, либо на вложенную иконку.
- Компонент не интерактивный: фокус-менеджмента и клавиатурных обработчиков нет.
- Язык не хардкодится: весь текст приходит от потребителя.

## Связанные компоненты

- `UnorderedList` — тот же маркированный список с data-driven API (`items`). Реализован как тонкая
  обёртка над `UnorderedListExtended`: разворачивает каждый элемент массива в `Item` и всегда добавляет
  `Item.Marker`. Типичная точка выбора: данные → `UnorderedList`, произвольная композиция →
  `UnorderedListExtended`. Правки в разметке и стилях здесь видны и в `UnorderedList`.
- `Text` — типографика элемента. `UnorderedListExtended.Item` рендерится как `Text` с `tag="li"`,
  поэтому props элемента (`size`, `type`, `weight`, `line`) — это props `Text`.
- `OrderedList` — нумерованный список для той же задачи, когда важен порядок пунктов.
