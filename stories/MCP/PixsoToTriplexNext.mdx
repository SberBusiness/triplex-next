<Subtitle>От ссылки на макет до React-компонентов Triplex Next</Subtitle>

[`@sberbusiness/pixso-to-triplex-next-mcp-server`](https://www.npmjs.com/package/@sberbusiness/pixso-to-triplex-next-mcp-server)
читает макет через Pixso MCP и превращает его в компактное дерево **TDIR**
(Triplex Design Intermediate Representation — промежуточное представление дизайна Triplex).
В дереве сохраняются структура, тексты, раскладка и сопоставления с компонентами Triplex Next.
React-код по этому дереву пишет AI-агент.

Подключайте пакет вместе с <a href="./?path=/docs/mcp-triplex-next--docs" target="_top">Triplex Next MCP</a>:
один сервер получает дизайн, второй помогает проверить API компонентов, токены и имена иконок.

> Пакет находится на ранней стадии: API инструментов и формат TDIR могут меняться до версии 1.0.

## Как устроена работа

```text
Ссылка на фрейм Pixso
  → Pixso MCP
  → pixso-to-triplex: get_design_tdir
  → дерево TDIR
  → AI-агент + triplex: документация компонентов
  → React-код на @sberbusiness/triplex-next
```

## Быстрый старт

Понадобятся Node.js 20 или новее, npm с командой `npx`, AI-клиент с поддержкой MCP
и доступ к макету в Pixso.

1. Получите токен в профиле Pixso и сохраните его в переменной окружения `PIXSO_MCP_TOKEN`,
   например в `~/.zshrc`.
2. Откройте макет в Pixso, выделите нужный фрейм и скопируйте ссылку на него.
3. Добавьте оба сервера в конфигурацию клиента: `.mcp.json` для Claude Code
   или `.cursor/mcp.json` для Cursor. Если `mcpServers` уже существует, дополните его.
4. Перезапустите MCP-серверы или клиент и проверьте, что оба сервера подключены.

```json
{
  "mcpServers": {
    "triplex": {
      "command": "npx",
      "args": ["-y", "@sberbusiness/triplex-next-mcp-server"]
    },
    "pixso-to-triplex": {
      "command": "npx",
      "args": ["-y", "@sberbusiness/pixso-to-triplex-next-mcp-server"],
      "env": {
        "PIXSO_MCP_URL": "http://pixso.design.sber.ru/api/mcp/mcp",
        "PIXSO_MCP_TOKEN": "${PIXSO_MCP_TOKEN}",
        "PIXSO_AUTH_STYLE": "dual"
      }
    }
  }
}
```

`npx` скачает пакеты при первом запуске. Токен не записывается в конфигурацию: клиент
подставит его из переменной окружения. В Cursor вместо `${PIXSO_MCP_TOKEN}` укажите
`${env:PIXSO_MCP_TOKEN}`.

### Ссылка на фрейм

Копируйте ссылку при выделенном фрейме или секции. Пример формата:

```text
https://<хост>/app/design/<fileKey>?item-id=<guid>
```

Поддерживаются параметры `item-id`, `itemId` и `node-id`. Ссылки только на файл без указания
узла недостаточно для выбора нужного экрана.

## Другие варианты подключения

Для другой инсталляции Pixso замените блок `env` у сервера `pixso-to-triplex`.
Адрес сервиса уточните для своей инсталляции, токен получите в профиле Pixso.

```json
{
  "PIXSO_MCP_URL": "https://<хост инсталляции>/api/mcp/mcp",
  "PIXSO_MCP_TOKEN": "${PIXSO_MCP_TOKEN}",
  "PIXSO_AUTH_STYLE": "bearer"
}
```

Это содержимое поля `env`, а не полная конфигурация MCP. Если всё же записываете реальный токен
в конфигурацию, храните её в пользовательских настройках клиента или в файле, исключённом из Git.

Для десктоп-клиента Pixso включите **Local MCP** в файловом меню, оставьте макет открытым
и укажите `PIXSO_MCP_URL` со значением `http://127.0.0.1:3667/mcp` без токена.

Для Remote MCP в настройках AI-клиента рекомендуется таймаут вызова от 120 секунд:
загрузка макета и дозапросы недостающих узлов могут занимать десятки секунд.

## Правила генерации для агента

Пакет содержит файл `pixso-to-triplex.md` с правилами чтения TDIR и генерации кода.
Чтобы агент мог прочитать его по стабильному пути в проекте, установите пакет локально:

```bash
npm install --save-dev @sberbusiness/pixso-to-triplex-next-mcp-server
```

Добавьте ссылку на правила в `AGENTS.md`, `CLAUDE.md` или инструкции вашего AI-клиента:

```text
Перед генерацией кода из макета Pixso прочитай целиком файл
node_modules/@sberbusiness/pixso-to-triplex-next-mcp-server/pixso-to-triplex.md
и соблюдай его правила.
```

## Первый запрос

```text
Реализуй экран по макету Pixso: <ссылка на фрейм с item-id>.

1. Прочитай pixso-to-triplex.md из установленного пакета и соблюдай его правила.
2. Вызови get_design_tdir сервера pixso-to-triplex с этой ссылкой.
3. В конце сообщи, какие части макета не удалось перенести точно.
```

Первый вызов `get_design_tdir` проверяет всю цепочку подключения к Pixso.
Статус MCP-сервера «подключён» подтверждает запуск процесса, но ещё не доступ к макету.

## Работа через OpenSpec

Для работы с `openspec` установите пакет локально, как описано в разделе
«Правила генерации для агента», и добавьте скриншоты необходимых
экранов из Pixso в директорию `mockups` внутри вашего change.

Затем добавьте инструкции в `rules.design` и `rules.tasks` вашего конфигурационного файла `openspec/config.yaml`.
Инструкции должны обязательно содержать указание использовать скилл `.gigacode/skills/pixso-screen/SKILL.md` при разборе макета и
ссылку на директорию со скриншотами для сверки. Пример:

```yaml
design:
  - >-
    Ссылки на макеты - в Context (канонический кадр в proposal.md, полный перечень кадров
    таблицей в design.md); в spec/** ссылок на Pixso и на файлы скриншотов не писать. Любой
    разбор макета Pixso - только по скиллу .gigacode/skills/pixso-screen/SKILL.md,
    прочитать его целиком до первой строки кода; в обход скилла макет не разбирать и MCP
    pixso-to-triplex не вызывать.
  - >-
    Скриншоты кадров макета лежат в директории mockups/ папки change; имя файла
    <подтип>-<item-id>.png с дефисом вместо двоеточия. В таблице кадров design.md
    каждый скриншот даётся ссылкой на файл. Экспортирует пользователь вручную:
    MCP pixso-to-triplex PNG не отдаёт. Нет файла - спросить,
    а не подменять его деревом TDIR.

tasks:
  - >-
    Если задача правит раскладку по макету Pixso, в её тексте должна быть ссылка на конкретный
    кадр или на таблицу кадров в design.md, а сама задача выполняться по скиллу
    .gigacode/skills/pixso-screen/SKILL.md.
  - >-
    Если в папке change есть директория mockups/, задача правки или сверки раскладки ссылается и на
    файл скриншота. Нормативы делятся: дерево TDIR отвечает за состав полей,
    скриншот - за то, как поля лежат в ряду.
```

Скилл `.gigacode/skills/pixso-screen/SKILL.md`:

```markdown
---
name: pixso-screen
description: >-
  Генерирует React-компонент на дизайн-системе @sberbusiness/triplex-next по ссылке на макет Pixso (дерево TDIR от MCP-сервера pixso-to-triplex)
  в указанный пользователем файл. Использовать, когда пользователь просит сделать/сгенерировать страницу или экран из макета Pixso.
---

Ты - фронтенд-разработчик. Сгенерируй React-компонент на дизайн-системе
@sberbusiness/triplex-next по дереву дизайна TDIR.

Вход:
  - Ссылка на макет Pixso.
  - Дерево TDIR получи сам: вызови get_design_tdir MCP-сервера pixso-to-triplex
  с этой ссылкой. Ответ из двух частей: сводка и JSON дерева. Работай по дереву:
  роли узлов, компоненты Triplex с props, тексты, сетка, отступы.
  - Генерация кода из макетов Pixso: перед работой прочитай целиком node_modules/@sberbusiness/pixso-to-triplex-next-mcp-server/pixso-to-triplex.md
  и соблюдай все правила из него.

Требования:
  1. Не выдумывай API: перед использованием каждого компонента из
  usedComponents вызови get_component сервера triplex. Имена иконок - только через list_icons.
  2. TypeScript strict: обязательные props заполняй заглушками, состояние и обработчики не нужны.
  3. Тексты и структуру бери из дерева; ничего не сокращай ради компилируемости.
  4. Узел с ролью unknown или диагностикой UNMAPPED_COMPONENT / DETACHED_INSTANCE:
  вызови get_design_dsl_slice с адресом из поля
  sliceNodeId диагностики - не больше 10 вызовов на экран и 2 по одному адресу;
  из среза бери только тексты, структуру и имена, не стили.
  5. Самопроверка: прогони tsc --noEmit и исправляй ошибки до нуля;
  затем сверь, что каждый текст из дерева (text.content и строковые props) дословно есть в коде.
  6. Если в задании дан путь к PNG-скриншоту макета, открой этот файл и сверь по нему.
  Что не читается с первого просмотра - рассматривай приближением, а не догадкой.
  7. В конце напиши короткий отчёт: какие компоненты использовал, где сомневался, что не смог отобразить,
  чем результат отличается от скриншота.
```

В файле `openspec/changes/.../design.md` создайте раздел **Макет** и поместите в него таблицу
с наименованием кадра, ссылкой на фрейм Pixso (формат — в разделе «Ссылка на фрейм»)
и названием PNG-файла из `mockups`.

Далее выполните команду `/opsx-apply`.

## Подготовка макета

Качество результата зависит от структуры исходного дизайна:

- Используйте инстансы библиотеки Triplex, сохраняйте связь с мастерами компонентов.
- Задавайте варианты через свойства компонент-сета, чтобы конвертер мог восстановить props.
- Вставляйте иконки из библиотеки и не переименовывайте их.
- Сохраняйте тексты текстовыми слоями, используйте автолейаут для раскладки.
- Выносите изображения в отдельные слои с понятными именами; служебные слои начинайте с `_`.
- Передавайте один экран или секцию за раз.

Для другой инсталляции Pixso точный маппинг может потребовать собственного реестра через
`TDIR_REGISTRY_PATH`. Изображения и скриншоты, недоступные через Remote MCP, нужно передать
агенту отдельно.
