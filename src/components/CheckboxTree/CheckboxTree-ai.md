# CheckboxTree

## Назначение

Дерево чекбоксов, которое строится из массива данных и само связывает состояние
родителей и потомков. Обёртка над `CheckboxTreeExtended`: разметку узлов
компонент формирует сам, потребитель передаёт только описание дерева
(`ICheckboxTreeCheckboxData[]`) и получает в `onChange` новый массив с
пересчитанными флагами `checked` и `bulk`.

Каскадная логика — единственное, что компонент добавляет к
`CheckboxTreeExtended`:

- выбор узла выбирает всех его потомков, снятие — снимает всех;
- если выбрана только часть потомков, родитель становится выбранным частично
  (`bulk`) и рисует bulk-иконку вместо галочки;
- клик по частично выбранному узлу выбирает поддерево целиком, а не снимает
  выбор;
- флаги пересчитываются снизу вверх по всему дереву на каждое изменение.

Используй когда: есть готовая иерархия значений (категории, права доступа,
фильтры) и нужна стандартная логика «родитель ↔ потомки» без ручного
пересчёта.

Не используй когда: нужна своя структура данных, произвольный контент рядом с
чекбоксом, ленивая загрузка ветки или другая логика связи родителя и потомков —
бери `CheckboxTreeExtended` и описывай узлы вручную. Если иерархии нет вовсе,
достаточно `CheckboxYGroup`.

## Варианты и props

`ICheckboxTreeProps` наследует `ICheckboxTreeExtendedProps` без `children` и
`onChange`, поэтому тип разрешает и остальные атрибуты `<ul>` (`className`,
`id`, `data-*`). Но компонент их не прокидывает — см. «Известные ограничения».
Фактически он использует только `checkboxes`, `onChange` и `size`.

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `checkboxes` | `ICheckboxTreeCheckboxData[]` | — | Описание дерева. Вложенность задаётся полем `children` элементов. Обязателен |
| `onChange` | `(options: ICheckboxTreeCheckboxData[]) => void` | — | Вызывается после каждого клика по чекбоксу — с новым массивом верхнего уровня и уже пересчитанными флагами. Обязателен |
| `size` | `EComponentSize` | `EComponentSize.MD` | Размер чекбоксов и отступов веток. Раздаётся через контекст `CheckboxTreeExtended`, в DOM не попадает. В мобильном представлении всегда `MD` |
| `children` | `never` | — | Запрещён типом: разметку узлов формирует сам компонент |

### `ICheckboxTreeCheckboxData`

Описание одного узла. Поля `checked` и `bulk` у узлов с потомками
пересчитываются компонентом — задавать их вручную имеет смысл только как
начальное состояние.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Идентификатор узла, уникальный в пределах всего дерева |
| `label` | `React.ReactNode` | Видимая подпись чекбокса. За счёт вложенности `<input>` в корневой `<label>` она же становится доступным именем |
| `checked` | `boolean` | Признак выбора |
| `bulk` | `boolean` | Признак частичного выбора: bulk-иконка вместо галочки |
| `children` | `ICheckboxTreeCheckboxData[]` | Вложенные узлы |

### Утилиты пересчёта

`utils.ts` экспортируется через barrel, поэтому три функции — часть публичного
API и переиспользуются, когда потребитель считает состояние дерева у себя
(например, кнопкой «выбрать всё»):

| Функция | Что делает |
|---|---|
| `traverseCheckboxes(checkboxes, callback)` | Обход в глубину **снизу вверх**: callback вызывается сначала для потомков, затем для родителя |
| `checkParentCheckboxes(checkbox)` | Пересчитывает `checked` / `bulk` узла по его прямым потомкам. Узел без потомков не трогает |
| `checkChildrenCheckboxes(checkbox)` | Проставляет `checked` узла всем его потомкам вниз по дереву |

Порядок обхода в `traverseCheckboxes` — не деталь реализации, а контракт:
`checkParentCheckboxes` работает корректно только если потомки уже пересчитаны.

## Дизайн-токены

Собственных стилей и токенов у компонента нет — он не содержит ни одного
LESS-модуля. Всё оформление приходит из `CheckboxTreeExtended` (отступы веток,
общий токен `Checkbox.BorderColor_Focus`) и из `Checkbox` (цвета, размеры,
состояния). Переопределять их нужно у этих компонентов — см.
`CheckboxTreeExtended-ai.md` и `Checkbox-ai.md`.

## Инварианты

- **Компонент мутирует переданные объекты.** `handleChange` пишет `checked` и
  `bulk` прямо в элементы массива `checkboxes`, а в `onChange` отдаёт поверхностную
  копию массива верхнего уровня (`[...checkboxes]`). Идентичность самих узлов при
  этом сохраняется. На этом держится связка с `useState` у потребителя (новая
  ссылка на массив → перерисовка), и это наблюдаемое поведение: переход на
  иммутабельный пересчёт — breaking change, а не рефакторинг.
- **`children` запрещён типом** (`children?: never`). Разметка узлов —
  ответственность компонента; своя разметка — это `CheckboxTreeExtended`.
- **`id` узла обязан быть уникальным во всём дереве.** По `id` строятся
  `prevNodeId` / `nextNodeId`, а по ним `TreeView` ведёт клавиатурную навигацию.
  Дубликаты ломают перемещение по дереву.
- **Порядок клавиатурного обхода задаётся порядком массива** на каждом уровне:
  соседями узла считаются элементы `checkboxes` (или `children`) по соседним
  индексам.
- **Дерево всегда полностью раскрыто** — флаг `isStaticCheckboxTreeExtended` в
  `CheckboxTreeExtended` прячет стрелки и раскрывает все узлы. Сворачивания у
  `CheckboxTree` нет по построению.
- **Публичный API** — имена `ICheckboxTreeProps`, `ICheckboxTreeCheckboxData`,
  функции `traverseCheckboxes`, `checkParentCheckboxes`,
  `checkChildrenCheckboxes` и состав barrel `index.ts` менять нельзя.
  `displayName` — `"CheckboxTree"`.

## Известные ограничения

Найдено при AI-рефакторинге (TRI-22). Поведение оставлено как есть — его меняют
только отдельным решением, это публичный контракт.

- **`forwardRef` у компонента нет — открытый вопрос, требует решения
  владельца.** Компонент объявлен как `React.FC`, повторяя
  `CheckboxTreeExtended` и `CollapsibleTreeExtended` (под капотом
  class-компоненты `TreeView` / `TreeViewNode` со своей работой с DOM). Это
  расходится с инвариантом «`forwardRef` обязателен» из `CLAUDE.md` и
  `docs/ai/CONTEXT.md`; прецедент правки — `CardStatic` в этом же релизе
  (TRI-19). В рамках TRI-22 не менялось: добавление `forwardRef` меняет тип
  экспортируемого компонента и требует правки нижнего слоя, то есть отдельной
  задачи на всё семейство Tree и записи в release notes.
- **Атрибуты `<ul>` не прокидываются.** Тип разрешает `className`, `id`,
  `data-*` и прочие props `ICheckboxTreeExtendedProps`, но компонент
  деструктурирует только `checkboxes`, `onChange` и `size` и рендерит
  `<CheckboxTreeExtended size={size}>` — остальное молча теряется. Переход на
  `...rest` по codestyle — наблюдаемое изменение, поэтому отдельное решение и
  запись в release notes, а не правка по ходу рефакторинга.
- **`bulk` у листа не пересчитывается.** `checkParentCheckboxes` выходит сразу
  для узла без потомков, поэтому флаг остаётся таким, каким его задал
  потребитель. Лист с `bulk: true` невозможно снять кликом: `checked` ставится
  по правилу «клик по частичному выбирает целиком». Задавать `bulk` листу не
  нужно — флаг осмыслен только для узлов с потомками.
- **`bulk` не сбрасывается, когда все потомки сняты.** В ветке «не выбран ни
  один потомок» пишется только `checked = false`. Визуально это незаметно:
  `Checkbox` показывает иконку (галочку или bulk) только при `checked`, а при
  следующем выборе флаг всё равно пересчитается.
- **`<li> cannot appear as a descendant of <li>`** — предупреждение React на
  первом рендере вложенных узлов. Приходит из `TreeView` и общее для всего
  семейства (`CollapsibleTree`, `CollapsibleTreeExtended`, `CheckboxTreeExtended`),
  лечится только на уровне `TreeView`.

## Accessibility

- Семантику (`<ul role="tree">`, `<li>`, группы) и клавиатурную навигацию
  обеспечивает `TreeView` через `CheckboxTreeExtended`. `CheckboxTree` добавляет
  к этому только связывание соседних узлов: каждому `CheckboxTreeExtended.Node`
  передаются `prevNodeId` и `nextNodeId` соседей по массиву.
- Фокус при навигации с клавиатуры забирает чекбокс активного узла — это делает
  `CheckboxTreeExtended.Checkbox`, подробности в `CheckboxTreeExtended-ai.md` →
  «Accessibility».
- Подпись чекбокса — поле `label`. Связь подписи и поля структурная: в
  `Checkbox` корневой элемент — `<label>`, а `<input type="checkbox">` лежит
  внутри него (`htmlFor` / `id` не используются), поэтому связь работает и при
  пустом `label` — только доступного имени у такого чекбокса не будет.
  Собственных текстов компонент не содержит: библиотека мультиязычная, и
  доступное имя для узла без видимой подписи передаёт потребитель через `label`.
- Частичный выбор кодируется только визуально (bulk-иконка). `aria-checked="mixed"`
  компонент не выставляет — под капотом нативный `<input type="checkbox">` без
  `indeterminate`. Если полумерное состояние нужно ассистивным технологиям,
  это отдельная доработка `Checkbox`.

## Связанные компоненты

- `CheckboxTreeExtended` (`src/components/CheckboxTreeExtended`) — нижний слой и
  одновременно альтернатива. `ICheckboxTreeProps` наследует его props, а
  `CheckboxTree` рендерит `CheckboxTreeExtended`, `.Node` и `.Checkbox`. Бери
  его, когда нужна своя разметка узлов или своя логика связи родителя и
  потомков.
- `Checkbox` (`src/components/Checkbox`) — чекбокс каждого узла. Отсюда приходят
  все токены, размеры и семантика `bulk` (иконка вместо галочки, видимость по
  `checked`).
- `CheckboxYGroup` (`src/components/Checkbox`) — плоская вертикальная группа
  чекбоксов. Подходит, когда иерархии нет и каскадный пересчёт не нужен.
- `MultiselectField` и `ChipMultiselect` — типовые потребители: показывают
  `CheckboxTree` как дерево опций внутри выпадающего блока (см. их stories).
