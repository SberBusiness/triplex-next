# SliderRange

## Назначение

Слайдер с двумя ползунками — готовая сборка `SliderExtended` для выбора диапазона: полоса,
два ползунка, трек между ними и метки уже собраны, потребителю остаётся задать границы, шаг,
метки и владеть парой значений.

Используй когда: пользователь выбирает диапазон из двух чисел и точность ввода не важна —
сумма «от и до», срок, процентный коридор.

Не используй когда:

- Нужен один ползунок — возьми `Slider`.
- Нужен нестандартный состав частей (без меток, без трека, своё содержимое ползунка) или
  собственная разметка подсказки — собери слайдер из `SliderExtended`.
- Нужно ввести точные границы — слайдер не заменяет пару `NumberField` / `AmountField`; при
  крупных диапазонах их обычно ставят рядом со слайдером.
- Ползункам нужны текстовые подписи для скринридера — `SliderRange` их передать не
  позволяет (см. Accessibility), собирай из `SliderExtended`.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `min` | `number` | Минимальное значение диапазона |
| `max` | `number` | Максимальное значение диапазона |
| `size` | `EComponentSize.MD \| EComponentSize.LG` | Размер. `SM` не поддерживается |
| `values` | `TSliderRangeValues` (`[number, number]`) | Текущая пара значений |
| `onChange` | `(values: TSliderRangeValues) => void` | Вызывается с отсортированной парой значений |
| `marks` | `ISliderRangeMark[]` | Метки под полосой: `{ value: number; label: React.ReactNode }` |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `step` | `number \| number[]` | `1` | Длина шага либо массив значений шагов. В массиве первое значение равно `min`, последнее — `max` |
| `draggableTrack` | `boolean` | `true` | Трек между ползунками перетаскивается целиком и сдвигает оба ползунка |
| `reverse` | `boolean` | `false` | Значения возрастают справа налево |
| `disabled` | `boolean` | `false` | Слайдер не активен: части не реагируют на курсор и выпадают из табуляции |
| `renderTooltipContent` | `(value: number) => React.ReactNode` | — | Содержимое подсказки над ползунком; вызывается для каждого ползунка со своим значением. Без этого prop подсказки не рендерятся вовсе |

Остальные атрибуты `React.HTMLAttributes<HTMLDivElement>` (включая `className`, `id`,
`aria-*`, `data-*`) уходят на **корневой `div`** слайдера. `children` запрещён
(`children?: never`): разметку собирает сам компонент.

### Особенности поведения

- **Компонент двигает ползунки сам.** Он рисует их по внутренним значениям и сообщает новую
  пару через `onChange`. `values` задаёт значения при монтировании и перезаписывает их, когда
  потребитель присылает новую пару. Поэтому ползунки сдвинутся, даже если потребитель
  проигнорирует `onChange`, — но тогда показанный диапазон разойдётся с его `values`.
  Обновляй `values` в `onChange`, иначе состояние на экране и в потребителе рассинхронизируются.
- **Наружу пара всегда уходит отсортированной.** Если ползунки поменялись местами,
  `onChange` получает `[меньшее, большее]`, а внутри компонент помнит, какой ползунок
  какой (см. «Инварианты» про `innerValues`).
- **Неотсортированные `values` компонент исправляет сам.** Если `values[0] > values[1]`,
  при монтировании и на каждом обновлении вызывается `onChange` с отсортированной парой.
  Потребитель, который проигнорирует этот вызов и продолжит присылать перевёрнутую пару,
  получит его снова на следующем обновлении; потребитель, который в ответ на него запишет
  в state новую перевёрнутую пару, зациклит обновления.
- **Перемещение трека меняет оба ползунка и вызывает `onChange` дважды подряд** — по
  вызову на ползунок. Первый вызов приходит с промежуточной парой, второй — с итоговой.
  Это же верно для стрелок на сфокусированном треке.
- **`step` числом строит шаги как `[...range(min, max, step), max]`.** Последний шаг всегда
  равен `max`, даже если он не кратен шагу: при `min: 0, max: 10, step: 3` шаги равны
  `0, 3, 6, 9, 10`.
- **`step` массивом задаёт произвольную шкалу.** Шаги равны визуально, а не по значению —
  так делается шкала сумм с укрупняющимся шагом (см. story `Amounts`). Массив, собранный
  инлайн в JSX, пересчитывает шаги на каждом рендере потребителя; вынеси его в константу.
- **Ползунки могут стоять в одной точке**, на один шаг они не «раздвигаются»: минимальной
  ширины диапазона у компонента нет.
- **Клик по полосе и по метке двигает ближайший ползунок** на ближайший шаг / на значение
  метки.
- **`marks` не обязаны совпадать с шагами.** Метка со значением вне `[min, max]`
  прижимается к краю полосы; `value` метки используется как React-ключ, поэтому дубли
  значений дадут предупреждение о неуникальных ключах.
- **Подсказки видны только при `:hover` и `:focus` ползунка** — управляются стилями, не
  props. Постоянно видимой подсказки нет, поэтому текущий диапазон обычно дублируют рядом
  со слайдером (так сделано в большинстве stories).
- **Ширину и внешние отступы задаёт потребитель.** Своей ширины у слайдера нет; собственные
  вертикальные отступы (под ползунки и под метки) он добавляет сам.

## Инварианты

- **`SliderRange` — class-компонент, и это часть публичного API.** `ref` на нём даёт
  инстанс класса, а не корневой `div` (в отличие от `Slider`, который обёрнут в
  `React.forwardRef`). Перевод в функциональный компонент или оборачивание в `forwardRef`
  сменит ref-target и тип компонента — breaking change.
- **Внутреннее состояние `innerValues` хранит значения в порядке ползунков, а не по
  возрастанию.** Так левый ползунок остаётся левым после того, как его перетащили за
  правый: наружу пара уходит отсортированной, а внутри порядок сохраняется. Синхронизация с
  `values` в `componentDidUpdate` учитывает это — когда ползунки перекрещены, новые `values`
  присваиваются в обратном порядке. Замена `innerValues` на отсортированный массив заставит
  ползунки перепрыгивать во время перетаскивания.
- **`onChange` вызывается внутри updater'а `setState` намеренно.** Перемещение трека меняет
  оба ползунка двумя вызовами подряд в одном батче, и второй обязан видеть значение,
  записанное первым, — иначе трек сдвинет только один ползунок. Побочный эффект: в
  `StrictMode` двойной вызов updater'а приводит к двойному вызову `onChange` с теми же
  значениями.
- **Пары значений сравниваются по склейке (`values.join("")`).** Из-за этого пары вроде
  `[1, 23]` и `[12, 3]` считаются одинаковыми, и переход между ними не обновит ползунки.
  Поведение историческое; чинить его нужно осознанно и вместе с release notes, потому что
  оно наблюдаемо.
- **`step` по умолчанию задан через `defaultProps`** (`1`). Значение по умолчанию —
  часть публичного контракта.
- **`children?: never`** — состав слайдера фиксирован, расширяется он только через
  `SliderExtended`.
- **`ISliderRangeProps` наследуется от `ISliderExtendedProps`**
  (`Omit<..., "onChange" | "step">`). Переименование props в `SliderExtended` ломает
  публичный API `SliderRange` — менять только вместе.
- **Порядок частей в разметке (`Rail` → `Dot` → `Track` → `Dot` → `Marks`) и наличие `Rail`
  обязательны.** Позиции клика и перетаскивания считаются от DOM-узла полосы; без `Rail`
  работает только клавиатура. `Tooltip` обязан лежать внутри `Dot`.
- **`renderTooltipContent` вызывается на каждом рендере** для каждого ползунка — держи её
  дешёвой и без side effects.
- Реализация остаётся React 17-совместимой (без `useId`, `useSyncExternalStore` и прочих
  React 18-only API): код синхронизируется в `release-0`.

## Accessibility

- **Каждый ползунок — `role="slider"`** с `aria-valuemin`, `aria-valuenow`, `aria-valuemax`
  из `min` / значения ползунка / `max` (рендерится `SliderExtended.Dot`).
- **Подписи ползункам `SliderRange` передать нельзя.** Все лишние props уходят на корневой
  `div`, а не на ползунки, поэтому `aria-label` / `aria-labelledby` окажутся на контейнере
  без роли. Если подписи «от» и «до» или `aria-valuetext` (нелинейная шкала, суммы, единицы
  измерения) обязательны — собирай слайдер из `SliderExtended` и передавай атрибуты прямо в
  `SliderExtended.Dot`.
- **Трек — `role="button"`**, потому что его можно перетаскивать клавиатурой. При
  `draggableTrack={false}` он выпадает из табуляции.
- **Клавиатура:** `ArrowLeft` / `ArrowDown` — шаг назад, `ArrowRight` / `ArrowUp` — шаг
  вперёд; на треке — шаг обоими ползунками сразу. Обработчики вызывают `preventDefault`,
  чтобы страница не скроллилась. `Home` / `End` / `PageUp` / `PageDown` не поддерживаются.
- **Порядок табуляции динамический.** Пока слайдер не в фокусе, в табуляцию попадает только
  ползунок с меньшим значением (`tabIndex` 0), второй исключён (`-1`). Как только фокус
  попал внутрь, элементы получают `tabIndex` 1 (левый ползунок), 2 (трек), 3 (правый
  ползунок). Побочный эффект положительных `tabIndex` — эти элементы встают в начало общего
  порядка табуляции страницы, пока слайдер в фокусе.
- **Метки кликабельны, но не фокусируются** и не читаются как элементы управления: это
  ускоритель для мыши, дублирующий клавиатурное перемещение по шагам.
- **Подсказки не связаны с ползунками через `aria`** — они показываются по `:hover`/`:focus`
  и для скринридера бесполезны; значения доступны через `aria-valuenow`.
- **`disabled` только визуальный и мышиный.** Части получают `pointer-events: none` и
  `tabIndex -1`, но нативного `disabled` у `span` нет: программно установленный фокус
  оставляет клавиатурное перемещение работающим — стрелки двигают ползунки и вызывают
  `onChange` так же, как у активного слайдера.

## Связанные компоненты

- `SliderExtended` (`src/components/SliderExtended/`) — составной слайдер, из которого
  собран `SliderRange`, и источник его props. Нужен, когда состава `SliderRange` не
  хватает: свой набор частей, своя подсказка, `aria`-атрибуты на ползунках.
- `Slider` (`src/components/Slider/`) — тот же слайдер на один ползунок: принимает `value`
  числом и не следит за порядком значений.
