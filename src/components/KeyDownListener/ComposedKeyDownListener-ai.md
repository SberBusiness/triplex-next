# ComposedKeyDownListener

## Назначение

Сервисный headless-компонент, композитор `KeyDownListener`. Принимает массив
конфигураций `keyDownListeners` и рендерит по одному `KeyDownListener` на элемент
массива — соседями к `children`. Каждый слушатель подписывается на `keydown` на
`window` независимо, поэтому компонент — это только способ описать несколько
горячих клавиш одним объявлением вместо ручного вложения нескольких
`KeyDownListener`.

Собственной разметки не рендерит: `children` выводятся как есть, без обёртки;
без `children` (и при любом наборе слушателей) DOM остаётся пустым — сами
`KeyDownListener` рендерят `null`.

Используй когда: у экрана или оверлея несколько глобальных горячих клавиш с
разными обработчиками — `Enter` подтверждает, `Esc` отменяет, стрелки листают.

Не используй когда:
- Клавиша всего одна — достаточно `KeyDownListener` напрямую.
- Клавиши разные, но обработчик один — у `KeyDownListener` `eventKeyCode`
  принимает массив кодов; различить нажатую можно по `event.keyCode`.
- Клавиша должна обрабатываться только внутри конкретного элемента — навесь
  `onKeyDown` на сам элемент: слушатели здесь глобальные и сработают при вводе в
  любое поле на странице.
- Нужно кликнуть по конкретной кнопке по нажатию клавиши — есть готовый
  `TriggerClickOnKeyDownEvent`.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `keyDownListeners` | `IKeyDownListenerProps[]` | Конфигурация слушателей. Из каждого элемента используются только `eventKeyCode` и `onMatch`; поле `children` элемента игнорируется — содержимое задаётся `children` самого композитора |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `children` | `React.ReactNode` | — | Рендерится как есть, без обёртки. При пустом `keyDownListeners` компонент сводится к `children` |

### Особенности поведения

- Слушатели рендерятся **соседями** к `children`
  (`<>{listeners}{children}</>`), а не оборачивают их. Поэтому `children` не
  зависят от длины и порядка массива: набор горячих клавиш можно менять между
  рендерами, содержимое при этом не перемонтируется — DOM-узлы, значения
  инпутов, фокус и анимации сохраняются.
- `onMatch` вызываются в порядке элементов `keyDownListeners`: слушатели
  монтируются в порядке массива, а `window` вызывает обработчики в порядке
  подписки. На нём завязан только порядок вызова — «перехватить» событие у
  соседнего слушателя нельзя, все подписаны на `window` независимо.
- Несколько элементов массива могут слушать одну и ту же клавишу — сработают
  все.
- Слушатели подписываются на `window` **до** `children`, потому что монтируются
  раньше них. Если внутри `children` есть собственный глобальный
  `keydown`-обработчик той же клавиши, `onMatch` сработает первым.
- Компонент ничего не мемоизирует: массив можно собирать инлайн в рендере.
  Каждый `KeyDownListener` читает свежие `eventKeyCode` и `onMatch` из props в
  момент события, переподписки на новые ссылки не происходит.
- `keyDownListeners` сопоставляются между рендерами по индексу (`key={index}`).
  Для элементов конфигурации это безопасно: `KeyDownListener` не рендерит
  разметку и не хранит внутренний state, поэтому переиспользование инстанса по
  позиции наблюдаемого эффекта не даёт.

## Инварианты

- **Имя prop `keyDownListeners`, `children` и интерфейс
  `IComposedKeyDownListenerProps`** (экспортируется из barrel
  `src/components/KeyDownListener/index.ts`) — публичное API, не менять.
- **Элементы `keyDownListeners` типизированы `IKeyDownListenerProps`** —
  переиспользование типа `KeyDownListener` осознанное; не заводить отдельный тип
  ради «более узкого» `Pick`, это сузит публичный контракт.
- **Плоский рендер слушателей** — не возвращаться к вложению
  (`reduce` с оборачиванием `children`): вложенность делает глубину дерева
  зависимой от длины массива и перемонтирует `children` при её изменении.
- **Собственной разметки нет** — не добавлять обёртку (`div`, `span`) вокруг
  `children`: потребители рассчитывают, что компонент прозрачен для layout,
  в том числе внутри flex/grid-контейнеров.
- **Без `forwardRef`** — осознанное исключение, как и у `KeyDownListener`:
  компонент не рендерит собственный host-элемент, форвардить `ref` некуда.
- Реализация остаётся React 17-совместимой (функциональный компонент без
  React 18-only API): код синхронизируется в `release-0`.

## Accessibility

- Собственной ARIA-семантики нет — компонент прозрачен для accessibility-дерева
  и не рендерит фокусируемых элементов.
- Горячие клавиши глобальные: перехватываются независимо от позиции фокуса и не
  анонсируются screen reader'ом. Действия, повешенные на клавиши, должны быть
  доступны и обычным путём (кнопкой) — шорткат не единственный способ выполнить
  действие.
- Компонент не проверяет, где находится фокус: `Enter` и `Esc` сработают и во
  время ввода в поле. Если это нежелательно, фильтруй в `onMatch` по
  `event.target`.

  `KeyDownListener` внутри библиотеки.
