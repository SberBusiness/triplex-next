# Запуск задачи из Linear (проект AI-Ready) — гайд для разработчика

Этот документ — для людей. Он описывает, как силами AI-агента (Claude Code)
провести задачу проекта «AI-Ready Phase 1» от постановки в Linear до PR,
и что в этом процессе остаётся за разработчиком.

Машинные инструкции, по которым работает агент, живут в `docs/ai/`
и `.agents/skills/` — этот файл их не заменяет, а показывает процесс сверху.

---

## Предусловия (один раз)

1. **Linear MCP.** В корне репозитория есть `.mcp.json`. При первом
   использовании авторизуйся: в Claude Code набери `/mcp` и пройди
   OAuth для `linear`.
2. **GitHub CLI.** `gh auth status` должен показывать активную сессию —
   через `gh` агент создаёт PR и запускает CI-workflow скриншотов.
3. **Чистое рабочее дерево.** Агент не начнёт задачу поверх чужих
   незакоммиченных изменений.
4. **(Опционально) Machine-аккаунт для агента.** Чтобы PR, комментарии
   и запуски workflow шли не от твоего имени, а от бота:
   - создай отдельный GitHub-аккаунт (machine account, ToS это разрешает),
     дай ему **Write** в репозитории;
   - сгенерируй fine-grained PAT: `contents: write`,
     `pull-requests: write`, `actions: write`;
   - положи токен в `~/.zshrc`: `export TRIPLEX_BOT_GH_TOKEN=...`
     (в репозиторий токен не попадает).

   Без токена всё работает от твоего аккаунта (fallback). С ботом-автором
   PR ты сможешь сам его апрувить. Подробности —
   `docs/ai/commits.md` § «GitHub-операции от аккаунта бота».

## Процесс целиком

```text
/create-task <описание>        # если задачи ещё нет; черновик → подтверждение
/take-task TRI-XXX             # план → подтверждение → In Progress → ветка → агент
        ... агент работает ...# рефакторинг, тесты, stories, AI.md, ревью
        ... автоматически ... # коммит → push → PR
        ... автоматически ... # visual baselines через CI + чистка orphan
        ... автоматически ... # finish-task: резюме в задачу, линковка PR
        ... code review ...   # человек смотрит PR
        merge                  # Linear сам переведёт задачу в Done
```

Точки, где процесс ждёт человека, помечены ниже как **[человек]**.

---

## Шаг 1. Задача в Linear

Если задачи ещё нет — `/create-task <короткое описание>`
(например `/create-task TextField AI-Ready`). Агент:

- сверится с кодом и `docs/ai/ROADMAP.md`, проверит дубликаты в Linear;
- покажет черновик: title, контекст, acceptance criteria, labels
  (`component:*`, `type:*`), проект «AI-Ready Phase 1».

**[человек]** Подтвердить черновик (или поправить). Без подтверждения
задача не создаётся.

**Важно про scope:** одна задача = один barrel-экспортируемый компонент.
Соседний компонент из той же директории (например MaskedField рядом
с TextField) — отдельная задача и отдельная строка ROADMAP. Внутренние
компоненты без barrel-экспорта (TextFieldBase) идут в scope родителя.

## Шаг 2. Взять задачу — `/take-task TRI-XXX`

Агент читает задачу, показывает план: компонент, тип работы, исполнитель
(обычно агент `ai-ready-builder` для label `type:ai-ready`), имя ветки.

**[человек]** Подтвердить план. После подтверждения агент сам:

- назначит задачу на тебя и переведёт в **In Progress**;
- создаст ветку `TRI-XXX-...` от актуального `main`;
- запустит исполнителя.

## Шаг 3. Работа агента

`ai-ready-builder` проводит компонент через полный цикл Phase 1:

1. AI-рефакторинг + unit-тесты (`component-refactorer`);
2. stories по modern pattern (`story-writer`);
3. `{Component}-ai.md` (skill `update-component-ai-md`);
4. независимое ревью (`change-reviewer`);
5. три ✅ в `docs/ai/ROADMAP.md`.

**[человек]** По ходу агент может задавать вопросы (scope, находки
в публичном API). Финальный AI.md стоит проглядеть глазами — разделы
«Назначение» и «Когда использовать» пишет модель.

## Шаг 4. Коммит, push, PR — автоматически

После зелёного ревью агент **без подтверждения**:

- коммитит по конвенциям `docs/ai/commits.md` (`TRI-XXX Описание`);
- пушит ветку и создаёт PR через `gh pr create`;
- GitHub-интеграция Linear привязывает PR и переводит задачу
  в **In Review**.

Автоматика останавливается и спрашивает при любом «гейте»: упавшие
проверки, изменение публичного поведения без release notes, блокеры
ревьюера, посторонние файлы в `git status`.

## Шаг 5. Visual baselines — автоматически

Если менялись stories или визуал, агент запускает skill
`update-visual-baselines`:

- триггерит GitHub Actions «Update Visual Snapshots» на ветке и ждёт;
- подтягивает коммит со свежими скриншотами (`git pull`);
- удаляет orphan-скриншоты переименованных/удалённых story
  (сверка с `storybook-static/index.json`) и пушит.

Скриншоты никогда не генерируются локально на macOS — только CI (Linux).
Пока идёт прогон, в ветку лучше не пушить: workflow может не суметь
запушить свой коммит.

## Шаг 6. Финализация — автоматически

Агент собирает резюме (что сделано, проверки, release notes, PR),
публикует его комментарием в задачу без подтверждения и проверяет,
что PR привязался. Отправленный текст показывается в отчёте — если
что-то не так, комментарий в Linear можно отредактировать постфактум.

Вручную `/finish-task` нужен только если автофинал был прерван
(тогда skill сначала покажет черновик комментария).

## Шаг 7. Ревью и мерж

**[человек]** Code review PR и мерж. Статусы дальше двигает
GitHub-интеграция Linear: merge → **Done**. Вручную Done не ставим.

Если ревьюеры оставили комментарии — `/address-pr-feedback`: агент
соберёт их, покажет план (что исправить, что ответить, что требует
твоего решения), после подтверждения внесёт правки, запушит и ответит
в тредах от твоего имени.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Linear MCP недоступен | `/mcp` → авторизация; проверь `.mcp.json` в корне |
| Агент остановился на «гейте» | Прочитай его вопрос — это осознанная пауза, реши и ответь |
| Visual workflow упал | Агент покажет `gh run view --log-failed`; один перезапуск — норм, дальше разбираться |
| Push workflow'а упал (ветка ушла вперёд) | Перезапустить прогон скриншотов после того, как ветка стабилизировалась |
| PR не привязался к задаче | Проверь, что имя ветки начинается с `TRI-XXX`; агент предложит перевести статус вручную |
