# MediaWidth

## Назначение

Сервисный headless-компонент адаптивности и точка входа в семейство `MediaWidth`.
Рендерит `children`, когда ширина окна браузера попадает в диапазон, заданный
`minWidth` и/или `maxWidth`, и `fallback` — во всех остальных случаях.
Собственной разметки не добавляет: в DOM попадает ровно тот элемент, который
выбран по медиа-запросу.

Сам подписку на медиа-запрос не выполняет — по набору переданных props делегирует
рендер в `MediaBetweenWidth`, `MediaMinWidth` или `MediaMaxWidth`, а те уже
используют `useMatchMedia`.

Используй когда: на определённой ширине окна нужно отрендерить **другое дерево**
компонентов, а не просто другие стили — мобильный вариант дропдауна вместо
десктопного, список вместо таблицы, компактная панель вместо развёрнутой.

Не используй когда:
- Разница между ширинами чисто визуальная (отступы, шрифт, раскладка) — это
  дешевле и надёжнее решается медиа-запросом в `*.module.less`, без
  перемонтирования поддерева.
- Граница — мобильная (`<768px`): для этого есть `MobileView`, частный случай с
  `maxWidth={EScreenWidth.SM_MAX}`.
- Нужно булево значение для props или условной разметки вокруг, а не выбор между
  двумя готовыми элементами — используй хук `useMatchMedia` (или `useMobileView`
  для мобильной границы).

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `children` | `React.ReactElement \| null` | Элемент для ширины внутри диапазона. `null` — внутри диапазона не рендерится ничего |
| `fallback` | `React.ReactElement \| null` | Элемент для ширины вне диапазона. Обязателен: prop без значения по умолчанию, для «ничего» передаётся явный `null` |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `minWidth` | `EScreenWidth` | — | Нижняя граница диапазона, включительно |
| `maxWidth` | `EScreenWidth` | — | Верхняя граница диапазона, включительно |

### Как комбинация props выбирает реализацию

| Переданы | Делегирует в | Медиа-запрос |
|---|---|---|
| `minWidth` и `maxWidth` | `MediaBetweenWidth` | `(max-width: {maxWidth}) and (min-width: {minWidth})` |
| только `minWidth` | `MediaMinWidth` | `(min-width: {minWidth})` |
| только `maxWidth` | `MediaMaxWidth` | `(max-width: {maxWidth})` |
| ничего | — | запрос не строится, `window.matchMedia` не вызывается |

### Особенности поведения

- **Без `minWidth` и `maxWidth` всегда рендерится `fallback`, а `children` — никогда.**
  Это штатное поведение, а не деградация: ветка «нет ограничений» трактуется как
  «условие не выполнено». Story `Fallback` фиксирует его специально. Если ширины
  приходят из props потребителя и могут быть `undefined` — учитывай, что
  «ограничений нет» здесь означает «показать `fallback`».
- **Границы включительные.** Значения `EScreenWidth` подобраны парами
  (`XS_MAX = 575px` / `SM_MIN = 576px`, `SM_MAX = 767px` / `MD_MIN = 768px` и
  т.д.), поэтому в `minWidth` передаётся `*_MIN`, в `maxWidth` — `*_MAX`. Так
  соседние диапазоны стыкуются без перекрытия и без «дыр» в один пиксель.
- **Согласованность `minWidth` и `maxWidth` не проверяется.** Если `minWidth`
  больше `maxWidth`, запрос просто никогда не сматчится и всегда будет рендериться
  `fallback` — ни предупреждения, ни ошибки не будет.
- **Ветки взаимоисключающие.** При пересечении границы одна ветка размонтируется,
  вторая монтируется: локальный state, фокус, значения неконтролируемых полей и
  текущие анимации внутри поддерева теряются. Состояние, которое должно
  переживать смену ширины, храни выше `MediaWidth` (или передавай его как props
  в обе ветки).
- Значение медиа-запроса читается синхронно на первом рендере (`useMatchMedia`
  вызывает `window.matchMedia` в инициализаторе `useState`), поэтому «мигания»
  неправильной ветки на первом кадре нет.
- Пересчёт при ресайзе идёт по событию `change` у `MediaQueryList`, а не по
  `resize` окна — слушатель снимается при размонтировании и переподписывается при
  смене строки запроса.
- **Компонент не SSR-safe:** `window.matchMedia` вызывается на первом рендере.
  Это поведение унаследовано от `useMatchMedia` и общее для всего семейства.

## Дизайн-токены

Собственных стилей и CSS-переменных нет — компонент не рендерит разметку.
Границы диапазонов задаются enum `EScreenWidth` (`src/helpers/breakpoints.ts`),
согласованным с LESS-переменными брейкпоинтов.

---

## Инварианты

- **Без `forwardRef` — осознанное исключение** из общего правила библиотеки:
  компонент не рендерит собственный host-элемент, форвардить `ref` некуда.
  Не добавлять и не убирать без отдельного решения — это публичный контракт.
- **Интерфейс props называется `IMediaProps`, а не `IMediaWidthProps`.**
  Рассинхрон с именем компонента исторический, интерфейс экспортируется из
  barrel — переименование будет breaking change. Не «чинить» походя: только
  отдельным решением с записью в release notes.
- **Имена и типы props `children`, `minWidth`, `maxWidth`, `fallback`** —
  публичное API, не менять. `fallback` остаётся обязательным: сделать его
  опциональным можно только осознанно, это меняет контракт у потребителей.
- **Значения `EScreenWidth`** — публичное API и общая сетка дизайн-системы. Не
  хардкодить пиксели в props и не заводить локальные брейкпоинты.
- **Делегирование в `MediaBetweenWidth` / `MediaMinWidth` / `MediaMaxWidth`** —
  не инлайнить `useMatchMedia` в `MediaWidth.tsx`. Строки медиа-запросов живут
  в трёх реализациях, и это единственное место, где они собираются.
- **Порядок веток в `if`/`else` значим:** проверка «оба props» идёт первой,
  иначе комбинация `minWidth + maxWidth` схлопнулась бы до одной границы.
- **Barrel `src/components/MediaWidth/index.ts`** экспортирует все четыре
  компонента и `useMatchMedia` — состав экспортов не сокращать.
- Реализация остаётся React 17-совместимой (без `useId`,
  `useSyncExternalStore` и прочих React 18-only API): код синхронизируется
  в `release-0`.
- **Fallback на устаревшие `addListener` / `removeListener`** в `useMatchMedia` —
  это поддержка старых браузеров, где `MediaQueryList` не наследует `EventTarget`
  и не имеет `addEventListener` (Safari < 14). К React 17 и синхронизации
  в `release-0` он отношения не имеет: удалять его вместе с React 17-совместимостью
  нельзя — это наблюдаемая регрессия у потребителей.

## Accessibility

- Собственной ARIA-семантики нет — компонент прозрачен для accessibility-дерева.
- Невыбранная ветка **не рендерится в DOM**, а не скрывается визуально: скринридер
  и последовательность табуляции видят только актуальный вариант. Дублирования
  контента для ассистивных технологий не возникает, но и «широкая» разметка на
  узком экране недоступна.
- Смена ветки при ресайзе удаляет из DOM сфокусированный элемент — фокус
  переходит на `<body>`. Если это критично (открытый оверлей, форма), верни
  фокус явно на стороне потребителя.
- Медиа-запрос завязан на ширину окна, а не на тип ввода: на десктопе с узким
  окном тоже рендерится «мобильная» ветка. Не завязывай на `MediaWidth` наличие
  touch-специфичных обработчиков как единственного способа взаимодействия.

## Связанные компоненты

Все три реализации живут в той же папке, экспортируются из того же barrel и
собственного AI.md не имеют — их контракт описан здесь.

> **Объём AI-рефакторинга.** В рамках TRI-58 отрефакторен только `MediaWidth.tsx`:
> соседние реализации и `useMatchMedia` были вне scope задачи. В их JSDoc
> остаются недочёты (опечатка «ширина экран» в `MediaMaxWidth` / `MediaMinWidth` /
> `MediaBetweenWidth`, `@param initial` без соответствующего параметра
> в `useMatchMedia`) — семейство ещё не вычищено целиком, это отдельная задача.

- `MediaBetweenWidth` (`src/components/MediaWidth/MediaBetweenWidth.tsx`) —
  диапазон между двумя границами. Props: `minWidth` и `maxWidth` **обязательные**,
  плюс `children` и `fallback`. Интерфейс `IMediaBetweenWidthProps`.
- `MediaMinWidth` (`src/components/MediaWidth/MediaMinWidth.tsx`) — только нижняя
  граница, `minWidth` обязателен. Интерфейс `IMediaMinWidthProps`.
- `MediaMaxWidth` (`src/components/MediaWidth/MediaMaxWidth.tsx`) — только верхняя
  граница, `maxWidth` обязателен. Интерфейс `IMediaMaxWidthProps`.
- `useMatchMedia` (`src/components/MediaWidth/useMatchMedia.ts`) — хук подписки на
  произвольный медиа-запрос, основа всего семейства. Принимает строку запроса,
  возвращает `boolean`. Годится и для не-ширинных запросов: `CarouselButton`
  использует его с `(pointer: coarse)`.
- `MobileView` (`src/components/MobileView/`) — частный случай `MediaWidth` с
  `maxWidth={EScreenWidth.SM_MAX}`, со своим AI.md. Для мобильной границы
  используется он, а не `MediaWidth` напрямую.

Разница между `MediaWidth` и тремя реализациями: у `MediaWidth` обе границы
опциональны и выбор реализации делается за потребителя; у реализаций
соответствующие границы обязательны. Прямое использование реализации оправдано,
когда набор границ известен статически и «пустая» комбинация невозможна по
построению.

### Потребители внутри библиотеки

Компонентом `MediaWidth`: `MobileView` (и, транзитивно, все его потребители).
Хуком `useMatchMedia`: `CarouselButton`, `useMobileView`.

В unit-тестах потребителей ветка задаётся подменой `window.matchMedia` (как в
`MediaWidth.test.tsx` и `Dropdown.test.tsx`) либо мокированием модуля
`useMatchMedia` (как в `IslandWidget.test.tsx`).

`mediawidth--mobile-view-story--xs.png` и `--xl.png`): на viewport `xs` (575px)
рендерится мобильная ветка, на `xl` (1200px) — `fallback`. Остальные stories
помечены `testRunner: { skip: true }` — их результат целиком определяется
шириной viewport и уже проверяется этой парой скриншотов.
