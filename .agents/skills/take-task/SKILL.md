# take-task

Начало работы над задачей из Linear (команда `TRI`).

## Предусловия

- Доступен Linear MCP (инструменты `mcp__linear__*`: `get_issue`, `list_issues`,
  `update_issue`, `list_issue_statuses` и т.п. — точные имена смотри в доступных
  инструментах). Если недоступен — сообщи пользователю: нужен `.mcp.json`
  в корне репозитория и авторизация через `/mcp`.
- Рабочее дерево чистое. Если есть незакоммиченные изменения — **остановись**
  и спроси пользователя, как поступить. Не прячь чужой WIP в stash молча.

## Воркфлоу

### 1. Определи задачу

- Если пользователь указал `TRI-XXX` — используй его.
- Если нет — запроси задачи команды TRI в статусах Todo/Backlog
  (отсортируй по приоритету), покажи краткий список и спроси, какую брать.

### 2. Прочитай задачу

`get_issue`: заголовок, описание, labels, проект, приоритет, связи
(blocked by / sub-issues). Прочитай комментарии, если есть — там могут быть
уточнения. Если задача заблокирована другой незакрытой задачей — сообщи
пользователю и не бери без подтверждения.

### 3. Покажи план и жди подтверждения

```text
Задача: TRI-XXX «{title}»
Компонент(ы): {из labels component:* или описания}
Тип: {из labels type:* или описания}

Что требуется: {выжимка описания + acceptance criteria}

Предлагаемый исполнитель:
  - ai-ready-builder     — label type:ai-ready / полный Phase 1 цикл
  - component-refactorer — label type:refactor
  - story-writer         — label type:stories
  - skill update-component-ai-md — label type:docs (только AI.md)
  - вручную в основном контексте — если задача не подходит ни под один шаблон

Ветка: TRI-XXX-{короткое-описание}
```

**Без подтверждения пользователя дальше не идёшь.**

### 4. Возьми задачу в Linear

- Назначь на текущего пользователя (assignee).
- Переведи в статус In Progress. Имя статуса не хардкодь — найди
  через `list_issue_statuses` статус типа `started`.

### 5. Создай ветку

От актуального `main` (см. `docs/ai/commits.md`):

```bash
git checkout main && git pull
git checkout -b TRI-XXX-короткое-описание
```

Имя — строчными буквами, слова через дефис, начинается с ID задачи.

### 6. Передай работу

Запусти выбранного агента/skill, передав в промпт: ID задачи, полный текст
описания и acceptance criteria. Агент работает по своим правилам
(план → подтверждение → правки → проверки).

## Жёсткие ограничения

- Один запуск = одна задача.
- Не меняй статус и assignee до подтверждения плана пользователем.
- Не коммить и не пушь — это отдельные шаги (`/commit-component`, `/finish-task`).
- Если Linear недоступен — не имитируй работу с трекером, просто сообщи.
