# release

Оркестратор релиза. Выпускает обе версии библиотеки по очереди:

```
1.Y.0  →  release-react18   (ветка main,      npm-тег latest)
0.Y.0  →  release-react17   (ветка release-0, npm-тег react17)
```

Сам ничего не коммитит и не публикует — вся механика в под-скиллах. Его
работа: проверить входные данные, запустить под-скиллы по очереди, не дать
второму стартовать при провале первого и собрать общий итог.

## Когда запускать

По явной просьбе выпустить релиз с указанием версии. Версия — обязательный
аргумент; если её нет — спроси, не угадывай и не выводи «следующую» сам.

Если нужна только одна половина — вызывай соответствующий под-skill напрямую:
[`release-react18`](../release-react18/SKILL.md) или
[`release-react17`](../release-react17/SKILL.md).

## Входные данные

- `VERSION` — React 18-версия, формат `1.Y.0`. Выпускаются только минорные
  релизы: `Y` = текущий минор + 1, патч всегда `0`.
- `V0` — `0.Y.0`, парная React 17-версия; минор совпадает с `VERSION`.

Разработчик может назвать любую из двух («выпусти 1.40.0» / «выпусти
0.40.0») — вторая выводится из минора. Если названы обе и миноры не
совпадают — остановись и спроси.

## 1. Предварительная проверка

Один общий взгляд до запуска под-скиллов, чтобы не выпустить `1.Y.0` и
только потом обнаружить, что вторая половина невозможна:

```bash
git status --porcelain
git fetch origin main release-0
node -p "require('./package.json').version"
git show origin/release-0:package.json | grep -m1 '"version"'
gh release view <VERSION> 2>&1 | head -3
gh release view <V0> 2>&1 | head -3
```

Проверки — при провале остановись и сообщи разработчику:

- Рабочее дерево чистое (исключение — заготовки release notes, созданные
  вручную).
- Ни `VERSION`, ни `V0` ещё не выпущены.
- Минор в `main` и в `release-0` совпадает — ветки не разъехались по версиям.
- `stories/release-notes/v1/<VERSION>.mdx` существует и **не пустой** — иначе
  публиковать нечего, релиза нет.

## 2. React 18 — `release-react18`

Запусти [`release-react18`](../release-react18/SKILL.md) с аргументом
`VERSION`. Он ведёт весь цикл: ветка `prerelease-<VERSION>` → бамп → PR →
зелёный CI → мерж → GitHub Release → публикация в npm.

**Гейт.** Если под-skill остановился на любом шаге — остановись и ты. Не
запускай React 17-часть: она опирается на уже опубликованную `1.Y.0` и на
её release notes в `main`.

Покажи разработчику итог первой половины (версия, PR, релиз, npm) прежде чем
идти дальше.

## 3. React 17 — `release-react17`

Запусти [`release-react17`](../release-react17/SKILL.md) с аргументом
`VERSION`. Он перельёт `main` в `release-0`, разрешит конфликты
React 17-адаптаций, прогонит локальные гейты, перенесёт notes и выпустит
`0.Y.0` с npm-тегом `react17`.

## 4. Общий итог

Собери в одном сообщении:

- `1.Y.0`: ссылка на PR, на GitHub Release, подтверждение `dist-tags.latest`;
- `0.Y.0`: ссылка на GitHub Release, подтверждение `dist-tags.react17`,
  перечень конфликтных файлов и как они разрешены, результат гейтов;
- подтверждение, что `dist-tags.latest` остался на `1.Y.0`;
- пути к созданным заготовкам notes (`1.(Y+1).0.mdx`, `0.(Y+1).0.mdx`);
- ссылки на Storybook обоих релизов.

Если вторая половина не выпущена — скажи это явно и назови причину.

## Преобразование MDX → release notes

Общий канон для обоих под-скиллов. Текст для GitHub Release получается из
`.mdx` механическим преобразованием:

| В MDX | В release notes |
|---|---|
| строка `import { ... } from "@storybook/addon-docs/blocks";` | удалить |
| `<Meta title="..." />` | удалить |
| `<Title>vX.Y.Z</Title>` | удалить |
| `<Heading>Текст</Heading>` | `## Текст` |
| всё остальное | без изменений |

Подряд идущие пустые строки схлопни в одну; убери пустые строки в начале
файла. Результат положи во временный файл в скретчпаде — **не** в репозиторий.

Готовый текст покажи разработчику перед созданием релиза.

## Жёсткие ограничения

- Не запускать без явно указанной версии.
- Не запускать React 17-часть, если React 18-часть не дошла до
  подтверждённой публикации в npm.
- Не подменять шаги под-скиллов «своими» командами — вся механика релиза
  живёт в них, здесь только последовательность и гейты.
