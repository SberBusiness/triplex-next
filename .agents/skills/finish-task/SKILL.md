# finish-task

Финализация задачи Linear после того, как изменения закоммичены.

## Предусловия

- Доступен Linear MCP (иначе — сообщи и остановись).
- В ветке есть коммиты задачи. Если есть незакоммиченные изменения —
  сначала предложи `/commit-component`.

## Воркфлоу

### 1. Определи задачу

Извлеки ID из имени ветки: `(TRI|TRIPLEX)-\d+`.

- `TRI-XXX` — задача в Linear, продолжай.
- `TRIPLEX-XXX` (legacy) — задачи в Linear может не быть; поищи по ID
  в заголовках, если нет — сообщи пользователю и заверши без действий в трекере.

### 2. Собери факты

- `git log main..HEAD --oneline` — коммиты задачи.
- `git diff main --stat` — затронутые файлы/компоненты.
- Обновлялись ли release notes (`stories/release-notes/v1/*.mdx` в diff).
- Вердикт `change-reviewer`, если он запускался в этой сессии.

### 3. Push и PR

- В воркфлоу задачи Linear пуш и PR уже выполнены автоматически на финале
  работы (см. `docs/ai/commits.md` § «Когда коммитить и пушить»). Проверь:
  `git status -sb` (ветка запушена?) и `gh pr view` (PR существует?).
- Если пуша/PR ещё нет (например, автоматический финал был прерван) —
  выполни недостающее сам: `git push -u origin <ветка>`, затем
  `gh pr create` с заголовком `TRI-XXX Краткое описание` (с учётом
  bot-токена — см. `docs/ai/commits.md` § «GitHub-операции от аккаунта
  бота»).
- Для веток вне задач Linear (legacy `TRIPLEX-XXX` и прочие) действует
  прежнее правило: пуш и PR — только по явному подтверждению пользователя.

### 4. Комментарий в задачу

`save_comment` в задачу TRI-XXX:

```markdown
## Резюме работы

**Сделано:** {1–3 предложения}
**Компоненты:** {список}
**Проверки:** tsc ✅/❌ · vitest ✅/❌ · eslint ✅/❌ · ревью: {вердикт change-reviewer / не запускался}
**Release notes:** обновлены / не требуются
**PR:** {ссылка, если есть}
```

**В автоматическом финале задачи Linear** (ветка `TRI-XXX` через `take-task`,
см. `docs/ai/commits.md`) комментарий публикуется **без подтверждения** —
покажи отправленный текст пользователю в отчёте; поправить можно постфактум,
комментарий редактируемый. **При запуске по явной просьбе вне автофинала**
покажи черновик и дождись подтверждения перед отправкой.

### 5. Статус

- Проверь через `get_issue`, привязался ли PR (GitHub-интеграция Linear
  линкует по `TRI-XXX` в имени ветки и двигает статусы сама:
  PR открыт → In Review, смержен → Done).
- Если PR не привязался или интеграции нет — предложи вручную перевести
  задачу в In Review (статус типа `started`/review — найди через
  `list_issue_statuses`).

## Жёсткие ограничения

- Не переводи задачу в Done вручную — Done наступает после мержа PR.
- Для веток вне задач Linear не пушь и не создавай PR без явного
  подтверждения (в ветках `TRI-XXX` пуш и PR — часть автоматического финала).
- Вне автоматического финала не отправляй комментарий без показа черновика
  (в автофинале — публикуй сразу, показав текст в отчёте).
