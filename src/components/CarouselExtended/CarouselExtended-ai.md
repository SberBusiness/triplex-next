# CarouselExtended

## Назначение

Горизонтально прокручиваемая лента произвольного контента с кнопками прокрутки.
Компонент владеет только прокруткой и состоянием кнопок: разметку кнопок, их
внешний вид и позиционирование задаёт потребитель через рендер-функции
`buttonPrev` и `buttonNext`.

Используй когда: контент выкладывается в один горизонтальный ряд, его ширина
заранее неизвестна (шаги процесса, применённые фильтры, теги, набор периодов), и
нужны кнопки прокрутки в оформлении конкретного продукта.

Не используй когда:

- Нужна слайдовая карусель с постраничной прокруткой, индикаторами, клавиатурой
  и touch-жестами — для этого есть составной `Carousel`
  (`src/components/Carousel/`) с `Viewport` / `Track` / `Item` / `Indicators`.
- Нужна лента шагов процесса — возьми `Stepper`, он уже собран на
  `CarouselExtended` и добавляет выравнивание по выбранному шагу.
- Контент заведомо помещается в контейнер — обычного блока достаточно,
  компонент не даст ничего, кроме скрытого скроллбара.
- Прокрутка нужна по вертикали — компонент прокручивает только по горизонтали.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `buttonPrev` | `(props: ICarouselExtendedButtonProvideProps) => React.ReactNode` | Рендер-функция кнопки «Назад». Вызывается на каждом рендере, результат ставится перед лентой |
| `buttonNext` | `(props: ICarouselExtendedButtonProvideProps) => React.ReactNode` | Рендер-функция кнопки «Вперёд». Результат ставится после ленты |
| `stepPrev` | `number` | Величина прокрутки в px за один клик по кнопке «Назад» |
| `stepNext` | `number` | Величина прокрутки в px за один клик по кнопке «Вперёд» |

`children` и остальные атрибуты `React.HTMLAttributes<HTMLDivElement>`
(`className`, `style`, `data-*`, обработчики) — опциональны и уходят на корневой
элемент.

### Что получают рендер-функции кнопок

`ICarouselExtendedButtonProvideProps` — это `React.ButtonHTMLAttributes`, но
фактически компонент передаёт ровно три поля:

| Поле | Когда выставляется |
|---|---|
| `disabled` | Достигнут соответствующий край ленты. Для `buttonPrev` — `scrollLeft <= 0`, для `buttonNext` — правый край |
| `hidden` | Прокрутка не нужна: `scrollWidth === clientWidth` |
| `onClick` | Всегда. Запускает анимированную прокрутку на `stepPrev` / `stepNext` |

### Особенности поведения

- **`hidden` — это подсказка, а не автоматическое скрытие.** Компонент всегда
  вызывает обе рендер-функции; решение принимает потребитель. Обычно `hidden`
  деструктурируют и возвращают `null` (так делают `Stepper` и все примеры).
  Если прокинуть `hidden` дальше на нативную кнопку, сработает HTML-атрибут
  `hidden` и кнопка скроется через `display: none` — в вёрстке на flex/grid это
  даёт другой результат, чем отсутствие узла.
- **Начальное состояние до первого измерения:** `hidden: true`,
  `prevDisabled: true`, `nextDisabled: false`. На первом кадре кнопок нет, они
  появляются после первого `useEffect`.
- **Когда пересчитывается состояние кнопок:** монтирование, смена `children`,
  `resize` окна, `scroll` документа и прокрутка самой ленты (`onScroll`).
  `ResizeObserver` не используется — изменение ширины контейнера **без** ресайза
  окна (раскрытие соседней панели, смена лейаута) само по себе пересчёта не
  вызывает. Состояние также обновится при любой прокрутке ленты.
- **Прокрутка анимирована** утилитой `scrollSmoothHorizontally`: 24 кадра через
  `requestAnimationFrame`. Клик во время анимации не отменяет предыдущую —
  анимации складываются.
- **Дробный шаг округляется вверх по модулю:** `Math.floor(-stepPrev)` и
  `Math.ceil(stepNext)`. Шаг `200.2` даёт прокрутку на `201` px в обе стороны.
- **Скроллбар скрыт стилями** (`scrollbar-width: none`, `-ms-overflow-style`,
  `::-webkit-scrollbar`). Прокрутка колесом, тачпадом и тач-жестом работает
  штатно, но визуального индикатора наличия скрытого контента нет — единственная
  подсказка для пользователя — кнопки.
- **Внутренний контейнер ленты не настраивается снаружи:** `className` и `style`
  уходят на корневой элемент, у прокручиваемого `div` только собственный класс.
  Поэтому `gap` между элементами задать нельзя — отступы вешаются на сами
  элементы (`marginRight` в примерах). Элементы ленты — flex-элементы: чтобы они
  не сжимались и лента действительно прокручивалась, им нужен `flex: 0 0 auto`.
- **`hidden` считается по `clientWidth`, а `nextDisabled` — по `offsetWidth`.**
  Значения расходятся, если у ленты появятся границы, padding-бокс с рамкой или
  горизонтальный скроллбар занимает место. Сейчас стили этого не допускают.

## Дизайн-токены

Собственных CSS-переменных у компонента нет: `CarouselExtended.module.less`
задаёт только раскладку прокручиваемой ленты (`display: flex`,
`position: relative`, `overflow-y: hidden` — из-за чего `overflow-x` вычисляется
в `auto`) и скрывает скроллбар во всех браузерных движках. Цвета и размеры
приходят из контента и из кнопок, которые рендерит потребитель.

## Инварианты

- **`forwardRef` указывает на прокручиваемый контейнер, а не на корневой
  элемент.** Это неочевидно и является публичным контрактом: `Stepper` читает по
  этому ref `scrollLeft`, `getBoundingClientRect` и напрямую прокручивает ленту.
  Переносить ref на корневой `div` нельзя.
- **`className`, `style` и `...rest` уходят на корневой элемент** — именно на нём
  потребитель строит раскладку (`display: flex`, `position: relative` для
  наложенных кнопок). Не переносить на ленту.
- **Порядок узлов в DOM:** `buttonPrev` → лента → `buttonNext`. Потребители
  позиционируют кнопки относительно ленты (`Stepper` — абсолютно поверх краёв),
  поэтому вставка дополнительных обёрток ломает их вёрстку.
- **Имена и типы публичных сущностей** — `CarouselExtended`,
  `ICarouselExtendedProps`, `ICarouselExtendedButtonProvideProps`, а также имена
  props `buttonPrev` / `buttonNext` / `stepPrev` / `stepNext` — часть публичного
  API. `ICarouselExtendedButtonProvideProps` выглядит опечаткой («Provide» вместо
  «Provided»), но переименование — breaking change и делается только отдельным
  решением с записью в release notes.
- **`buttonPrev` и `buttonNext` — обязательные рендер-функции**, а не
  `React.ReactNode`. Они вызываются во время рендера, поэтому не должны содержать
  side-эффектов и собственных хуков.
- **`displayName`** равен `"CarouselExtended"`.
- **Класс `carouselExtended`** — единственный якорь прокручиваемого контейнера,
  на него опираются unit-тесты.
- Реализация остаётся React 17-совместимой (без `useId`,
  `useSyncExternalStore` и прочих React 18-only API): код синхронизируется
  в `release-0`.

## Accessibility

- Компонент не добавляет ролей и aria-атрибутов: ни корневой элемент, ни лента не
  интерактивны и прозрачны для accessibility-дерева.
- **`aria-label` кнопок — обязанность потребителя.** Компонент не хардкодит текст,
  библиотека мультиязычная. В примерах кнопки подписаны
  `aria-label="Прокрутить назад"` / `"Прокрутить вперёд"`.
- `disabled` приходит в рендер-функцию: если прокинуть его на нативную `<button>`
  (как делают `ButtonIcon` и примеры), кнопка на краю ленты корректно выпадает из
  порядка табуляции и не читается как активная.
- Кнопки — вспомогательная навигация, а не единственный способ добраться до
  контента: лента прокручивается колесом, тачпадом и тач-жестом. Для
  клавиатурной прокрутки самой ленты контейнер должен попасть в фокус — своего
  `tabIndex` у него нет. Если контент внутри некликабельный (текст, теги без
  обработчиков), добавь фокусируемую обёртку на стороне потребителя.
- Прокрутка кнопкой не переносит фокус и не меняет DOM-порядок — контент,
  уехавший за край, остаётся доступным скринридеру и табуляции.
- `Stepper` дополнительно ставит кнопкам `tabIndex={-1}`: там прокрутка
  дублируется выбором шага, и кнопки намеренно исключены из табуляции. Это
  решение потребителя, а не поведение `CarouselExtended`.

## Связанные компоненты

- `Stepper` (`src/components/Stepper/`) — единственный потребитель внутри
  библиотеки и единственное место, которое опирается на хрупкую деталь: ref
  указывает на прокручиваемую ленту. `Stepper` передаёт объектный ref, считает
  шаги прокрутки через собственный `ResizeObserver` и сам выравнивает выбранный
  шаг, меняя `scrollLeft`. Любое изменение ref-таргета или порядка узлов сломает
  его в первую очередь.
- `Carousel` (`src/components/Carousel/`) — современная слайдовая карусель со
  своим составным API (`Carousel.Viewport`, `Carousel.Track`, `Carousel.Item`,
  `Carousel.Indicators`, `Carousel.PrevButton` / `NextButton`), клавиатурой и
  touch-жестами. Решает соседнюю задачу: там прокрутка постраничная или по
  элементам, здесь — свободная лента произвольного контента. В таблице
  `docs/ai/ROADMAP.md` пока нет, поэтому в `related` не указан.
- `ButtonIcon` (`src/components/Button/ButtonIcon.tsx`) — то, что обычно
  возвращают рендер-функции кнопок: он принимает `disabled` и `onClick` без
  дополнительной обвязки. Компонент его не импортирует, выбор кнопки за
  потребителем.
- `scrollSmoothHorizontally` (`src/utils/scroll.ts`) — публичная утилита, на
  которой построена анимация прокрутки. Тот же хелпер использует `Stepper`.

viewport'ах отличаются только окружением.
