# Suggest

## Назначение

Headless-основа выпадающего списка с фильтрацией по введённому значению. Собственной
разметки не добавляет: рендерит `<div>`-обёртку и раздаёт потомкам через `SuggestContext`
значение поля ввода, видимость выпадающего списка и обработчики выбора, фильтрации и
клавиатуры. Управляющий элемент (поле ввода, чипс, кнопка) и сам выпадающий список пишет
потребитель — хук `useSuggestContext` отдаёт всё нужное состояние.

Внутри библиотеки на этой основе построен `ChipSuggest`. `SuggestField` решает ту же
задачу, но собственной реализацией состояния — на `Suggest` он пока не переведён
(в `SuggestField.tsx` стоит `TODO: Переписать через useSuggest`).

Используй когда: нужен suggest с нестандартным управляющим элементом или нестандартным
выпадающим списком, а готовые `SuggestField` / `ChipSuggest` не подходят по разметке.

Не используй когда:
- Нужно обычное поле-suggest с лейблом, статусами и кнопкой очистки — возьми
  `SuggestField`, он уже собран.
- Нужен suggest-фильтр в ряду чипсов — возьми `ChipSuggest`.
- Список не фильтруется вводом — возьми `SelectField` или `Dropdown` напрямую.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `value` | `T \| undefined` | Выбранная опция. Контролируемое значение: при его смене поле ввода перезаписывается на `value.label` |
| `options` | `T[]` | Список опций. Фильтрацию делает потребитель в `onFilter` — компонент список не фильтрует |
| `size` | `EComponentSize` | Размер. Suggest его **не отображает и не кладёт в контекст** — свойство существует, чтобы не попасть в DOM атрибутом; раздавай размер управляющему элементу и списку сам |
| `onSelect` | `(value: T \| undefined) => void` | Вызывается после выбора опции. Перед вызовом список закрывается, а в поле ввода подставляется `label` выбранной опции |
| `onFilter` | `(value: string) => void` | Вызывается на каждое изменение поля ввода. Ответ — обновлённый `options` |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `placeholder` | `string` | — | Текст подсказки. Только раздаётся через контекст, компонент его не рендерит |
| `noOptionsText` | `string` | — | Текст при пустом `options`. Рендерится в мобильном наполнении, в десктопном — потребителем |
| `loading` | `boolean` | — | Флаг загрузки. В мобильном наполнении рисует лоадер в шапке, в десктопном — на усмотрение потребителя |
| `dropdownListLoading` | `boolean` | — | Флаг догрузки списка: лоадер под уже загруженными опциями |
| `tooltipOpen` | `boolean` | — | Управление видимостью Tooltip у потребителя. Suggest только раздаёт значение через контекст |
| `clearInputOnFocus` | `boolean` | — | Очищать поле ввода при получении фокуса. Обработчик `onFocus` пишет потребитель — Suggest ничего не слушает |
| `onScrollEnd` | `() => void` | — | Доступные опции закончились при скролле списка. В мобильном наполнении вызывается автоматически |
| `onKeyDown` | `React.KeyboardEventHandler` | — | Обработчик клавиатуры на корневом `<div>`. Вызывается после внутренней обработки `Escape` |

Все остальные `React.HTMLAttributes<HTMLDivElement>` (кроме `onSelect`) попадают на
корневой `<div>`: `className`, `id`, `data-*`, `aria-*`, `style`.

### Что даёт `useSuggestContext`

Помимо перечисленных выше props потребитель получает состояние, которого нет во внешнем API:

| Поле | Описание |
|---|---|
| `inputValue` / `setInputValue` | Текущий текст поля ввода. `setInputValue` не вызывает `onFilter` |
| `dropdownOpen` / `setDropdownOpen` | Видимость списка. `setDropdownOpen(false)` не сбрасывает поле ввода |
| `closeDropdown(newInputValue?)` | Закрывает список и возвращает в поле `newInputValue` либо `label` текущего `value` |
| `activeDescendant` / `setActiveDescendant` | Идентификатор элемента, выделенного клавиатурой, для `aria-activedescendant`. Библиотека его не выставляет — клавиатурную навигацию по списку реализует потребитель. `setActiveDescendant` приходит в контекст из `useSuggest` в рантайме, но в типе значения контекста не объявлен — типизация поля меняет публичный тип `SuggestContext`, решение за мейнтейнером |
| `dropdownListId` | Сгенерированный `dropdown-list-{n}` для `id` списка и `aria-controls` на управляющем элементе |
| `suggestRef` | Ссылка на корневой `<div>`. Годится как `targetRef` для `Dropdown` |
| `dropdownRef` | Ссылку **обязан заполнить потребитель**, повесив её на выпадающий список. По ней Suggest отличает клик внутри списка от клика вне компонента |
| `onSelect` / `onFilter` | Обёртки над одноимёнными props: дополнительно обновляют `inputValue` и закрывают список |

### Опция (`ISuggestOption`)

`id` (уникальный, используется как ключ и для сравнения с `value`), `label` (текст в поле
ввода и в списке), `content` (кастомная разметка опции в списке вместо `label`),
`showNotificationIcon` (значок новых уведомлений).

Тип опции расширяется дженериком: `<Suggest<IMyOption> ...>` протаскивает `IMyOption`
в `value`, `options` и `onSelect`.

## Дизайн-токены

Собственных токенов нет: единственный стиль компонента —
`styles/SuggestDropdown.module.less` — задаёт высоту и отступы мобильного наполнения
фиксированными значениями. Внешний вид определяют компоненты, которыми потребитель
собирает управляющий элемент и список (`TextField`, `Chip`, `Dropdown`), — их токены
переопределяются через `ThemeProvider` в соответствующих AI.md.

## Инварианты

- `forwardRef` на `Suggest` — не убирать. Ref указывает на корневой `<div>`, тот же элемент
  попадает в `suggestRef` контекста.
- Корневой элемент — `<div>`. На него же вешается внутренний `onKeyDown`, поэтому событие
  клавиатуры от любого потомка проходит через обработчик `Escape`.
- `size`, `onSelect`, `onFilter` и `onKeyDown` намеренно исключаются из `...restProps` —
  иначе React отрендерит невалидные атрибуты на `<div>` и потеряет внутреннюю обработку.
- Закрытие по клику вне работает только если потребитель заполнил `dropdownRef`. Список
  обычно живёт в портале и корневым `<div>` не покрывается.
- `Escape` останавливает всплытие **только когда список открыт** — на этом строится
  вложенность suggest'а в модальные окна: закрытым suggest'ом `Escape` пробрасывается выше.
- Имена полей контекста — публичный API: `SuggestContext` и `useSuggestContext`
  экспортируются из barrel и используются вне папки компонента (`ChipSuggest`).
- `SuggestMobileDropdownContent` из barrel **не экспортируется**, но импортируется
  `ChipSuggest` по прямому пути. Переименование файла ломает `ChipSuggest`.

## Accessibility

Собственных ARIA-атрибутов Suggest не выставляет — разметку управляющего элемента и
списка пишет потребитель. Компонент даёт для этого:

- `dropdownListId` — общий идентификатор для `id` списка и `aria-controls` на управляющем
  элементе;
- `dropdownOpen` — значение для `aria-expanded`;
- `activeDescendant` / `setActiveDescendant` — для `aria-activedescendant` при клавиатурной
  навигации по списку.

Клавиатура: обработан только `Escape` — при открытом списке он закрывает список,
возвращает в поле ввода `label` текущего `value` и останавливает всплытие события.
Стрелки и `Enter` обрабатывает список потребителя (`DropdownList` / `DropdownListItem`
делают это сами). Возврат фокуса на управляющий элемент после закрытия Suggest не делает —
в `ChipSuggest` это решается `FocusTrap` вокруг содержимого дропдауна.

Мобильное наполнение (`SuggestMobileDropdownContent`) рендерит список с `role="listbox"`
и опциями `role="option"` с `aria-selected`, поле ввода получает автофокус при открытии.

## Связанные компоненты

- `SuggestField` — готовое поле-suggest с лейблом, статусами, префиксом/постфиксом и
  очисткой. Решает ту же задачу «из коробки»; на `Suggest` не построен и дублирует его
  состояние своей реализацией.
- `Chip` — родитель `ChipSuggest`, единственного компонента библиотеки, собранного на
  `Suggest`. `ChipSuggest` опирается не только на barrel, но и на внутренний
  `SuggestMobileDropdownContent`.
- `Dropdown` — мобильное наполнение Suggest рендерится из его частей
  (`DropdownMobileHeader`, `DropdownMobileInput`, `DropdownMobileList`, …); в десктопной
  композиции `Dropdown` обычно и служит выпадающим списком.
- `SuggestMobileDropdownContent` — внутреннее наполнение полноэкранного мобильного
  дропдауна: поле ввода, список опций, лоадер и текст при пустом списке. Данные берёт из
  `SuggestContext`, поэтому рендерится только внутри `Suggest`. Отдельного AI.md не имеет,
  из barrel не экспортируется.

Скриншот-тестами покрыты только `VisualTests` и `VisualTestsDropdownListLoading`:
набор исключён из скриншотов на уровне `meta` (`testRunner: { skip: true }`), а эти две
стори включены обратно через `testRunner: { skip: false }` — как в `ModalWindow`.
Suggest headless: собственной разметки он не рендерит, поэтому в кадре закрытых стори
только обвязка примеров (`TextField`, `Dropdown`), у которых своё визуальное покрытие,
а baseline `Default` и `DropdownListLoading` совпадали побайтово. Ценность есть лишь
у кадров с открытым списком, которые ставит `play`-функция.
