# Skeleton

## Назначение

Плейсхолдер-блок на месте контента, который ещё не загрузился: скруглённый прямоугольник, пульсирующий цветом фона. Форму и размер задаёт не компонент, а потребитель — собственных размеров у `Skeleton` нет.

Используй когда: известна будущая раскладка экрана и нужно показать её каркас во время загрузки — карточки, строки списка, аватары, блоки текста. Скелетон сохраняет геометрию страницы и не даёт контенту «прыгать» после загрузки.

Не используй когда:
- Раскладка заранее неизвестна или загрузка короткая — возьми спиннер: `LoaderSmall` (внутри кнопки/поля), `LoaderMiddle` (внутри блока), `LoaderScreen` (поверх области с затемнением).
- Нужно перекрыть уже отрисованный контент на время обновления — это `LoaderScreen`, а не скелетон.
- Нужен просто пустой отступ — `Gap`.

## Варианты и props

### Обязательные props

Обязательных props нет.

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `type` | `ESkeletonType` | `ESkeletonType.TYPE_2` | Цветовая схема пульсации под фон, на котором лежит скелетон. |

Компонент расширяет `React.HTMLAttributes<HTMLDivElement>` — принимает все стандартные атрибуты `<div>` (`className`, `style`, `aria-*`, `data-*` и т.д.).

### Значения `ESkeletonType`

| Значение | Заливка | Для какого фона |
|---|---|---|
| `TYPE_1` | Непрозрачные нейтральные серые | Светло-серые поверхности, где полупрозрачность «проваливается» и скелетон плохо виден |
| `TYPE_2` (по умолчанию) | Полупрозрачный тёмный тинт | Обычные светлые поверхности (белая карточка, фон страницы) |
| `TYPE_3` | Полупрозрачный светлый тинт | Тёмные и брендовые цветные поверхности |

`TYPE_2` и `TYPE_3` — полупрозрачные: результат зависит от того, что лежит под скелетоном. В тёмной теме пары токенов инвертированы, поэтому смысл («тинт по контрасту к своей поверхности») сохраняется в обеих темах и подбирать `type` под тему вручную не нужно — только под фон.

### Ограничения

- **У компонента нет собственных размеров.** В стилях заданы только `border-radius: 16px` и `flex-grow: 1`. Без размера от потребителя скелетон схлопнется в нулевую высоту. Задавай размер одним из способов: `style`/`className` с `width`/`height`, либо положи скелетон во flex-контейнер с заданной высотой — тогда сработает `flex-grow`.
- `border-radius` фиксирован в стилях и через props не настраивается — перекрывается только собственным `className`/`style`.
- `Skeleton` задуман как пустой плейсхолдер. `children` технически проходят на корневой `<div>` через spread и отрисуются, но контент внутри пульсирующего блока не предусмотрен дизайном — каркас из нескольких блоков собирается композицией нескольких `Skeleton` в разметке потребителя.

## Дизайн-токены

Переопределяются через `ThemeProvider` (prop `tokens`) — см. `ThemeProvider-ai.md` →
«Как переопределять токены». Значения по умолчанию — `src/components/DesignTokens/components/Skeleton.ts`.

```text
Skeleton.BackgroundColor_Type1_Start
Skeleton.BackgroundColor_Type1_End
Skeleton.BackgroundColor_Type2_Start
Skeleton.BackgroundColor_Type2_End
Skeleton.BackgroundColor_Type3_Start
Skeleton.BackgroundColor_Type3_End
```

Пара `Start`/`End` задаёт ключевые кадры пульсации: `Start` — состояние на 0% и 100%, `End` — на 50%. Переопределять их имеет смысл только парой, иначе анимация станет несимметричной.

## Инварианты

- **`forwardRef`** — обязателен, не убирать. `ref` пробрасывается на корневой `<div>`.
- **Имена публичного API**: компонент `Skeleton`, интерфейс `ISkeletonProps`, prop `type`, enum `ESkeletonType` и его строковые значения (`"type_1"`, `"type_2"`, `"type_3"`) — менять нельзя (breaking change).
- **Дефолт `type` — `ESkeletonType.TYPE_2`.** Смена дефолта меняет внешний вид у всех, кто не передаёт `type` явно.
- **`barrel src/components/Skeleton/index.ts`** экспортирует `./Skeleton` и `./enums` — оба экспорта сохранять.
- **Корневой DOM-элемент — `<div>`** без ARIA-роли; собственного содержимого компонент не рендерит.
- **`data-tx`** проставляется после спреда `...htmlDivAttributes`, то есть потребитель его не перекрывает. Порядок атрибутов в JSX не менять.
- **CSS-классы `skeleton`, `type1`, `type2`, `type3`** в `Skeleton.module.less` проверяются unit-тестами. Visual baseline (`loaders-skeleton--visual-tests`) фиксирует только геометрию из `.skeleton`: в story анимация выключена декоратором, а фон задан inline, поэтому цвета типов визуальным тестом не покрыты — классы `type1/2/3` объявляют лишь `animation`, а цвет приходит из `@keyframes`.
- **`displayName = "Skeleton"`** — проверяется тестом.
- **Анимация задаётся только в LESS** (`skeleton-type{N}-pulse`, 2s ease-in-out infinite). Имена keyframes локальны для CSS-модуля; потребитель гасит анимацию своим `className`/`style` (story `Visual tests` для скриншотов делает это глобальным правилом `* { animation: none !important; }` в декораторе).

## Accessibility

Компонент не интерактивный и по смыслу декоративный: в штатном использовании это пустой `<div>` без роли, без текста, без фокуса. ARIA-семантику загрузки компонент намеренно не хардкодит — её задаёт потребитель на контейнере загружаемой области:

- пометь область `aria-busy="true"` на время загрузки и сними атрибут после;
- если пользователю нужно объявление о загрузке — сделай `aria-live`-регион с текстом рядом, скелетон для этого не подходит (библиотека мультиязычная, компонент не содержит текста);
- сами скелетоны имеет смысл скрыть от скринридера (`aria-hidden="true"` через spread) — иначе в дереве доступности остаются пустые узлы.

Ограничение: пульсация не отключается по `prefers-reduced-motion` — если это важно, гаси анимацию своим `className`.

## Связанные компоненты

- `LoaderSmall` (`src/components/Loader/`) — спиннер для встраивания в кнопку или поле: альтернатива, когда каркас контента неизвестен.
- `LoaderMiddle` (`src/components/Loader/`) — спиннер для блока/секции: альтернатива на тех же основаниях.
- `LoaderScreen` (`src/components/LoaderScreen/`) — оверлей с затемнением поверх области: используется, когда контент уже отрисован и обновляется, а не загружается впервые.
