# CarouselViewport

## Назначение

Область просмотра составного `Carousel`: обрезает ленту по своим границам,
применяет отступы родителя и обрабатывает touch-жесты. Передаёт свой DOM-узел
в контекст, чтобы `Carousel` измерял доступный размер и рассчитывал прокрутку.

Используй внутри `Carousel`, оборачивая одну `Carousel.Track` со слайдами.
Для одной карусели предусмотрены один `Viewport` и одна лента. Самостоятельной
прокрутки и геометрии вне родителя нет; для свободно прокручиваемой ленты
рассмотри `CarouselExtended`.

Публичное обращение — `Carousel.Viewport` через
`import { Carousel } from "@sberbusiness/triplex-next"`.
Именованного экспорта `CarouselViewport` из пакета нет;
`ICarouselViewportProps` экспортируется из публичного barrel семейства.

```tsx
import React from "react";
import { Carousel } from "@sberbusiness/triplex-next";

export const CardsCarousel = () => (
    <Carousel viewportPadding={[8, 16]} style={{ width: 400, height: 180 }}>
        <Carousel.Viewport>
            <Carousel.Track>
                {["Первая карточка", "Вторая карточка", "Третья карточка"].map((text, index) => (
                    <Carousel.Item key={text} index={index} style={{ width: 240, height: 164 }}>
                        {text}
                    </Carousel.Item>
                ))}
            </Carousel.Track>
            <Carousel.PrevButton aria-label="Предыдущая карточка" />
            <Carousel.NextButton aria-label="Следующая карточка" />
        </Carousel.Viewport>
    </Carousel>
);
```

Кнопки внутри области появляются при наведении на неё; клавиатурный фокус
также делает саму кнопку видимой. Индикаторы страниц размещай рядом с
`Viewport`, чтобы они не попадали под `overflow: hidden`.

## Варианты и props

Обязательных props и собственных вариантов оформления нет.
`ICarouselViewportProps` наследует HTML-атрибуты `<div>`.

| Prop | Назначение и ограничения |
|---|---|
| `children` | Лента `Carousel.Track` со слайдами и необязательные кнопки навигации |
| `className` | Объединяется через `clsx` с внутренним классом `viewPort` |
| `style` | Передаётся на корневой `<div>`; внутренняя runtime-переменная padding применяется после пользовательского объекта |
| `onTouchStart` | Вызывается после инициализации жеста и установки глобальных listeners. При пустом `targetTouches` не вызывается; `preventDefault` в callback не отменяет уже начатый жест |
| `onTouchMove`, `onTouchEnd`, `onTouchCancel` и остальные HTML-обработчики | Передаются на `<div>`. Встроенные move/end/cancel слушают `window`; это отдельные native listeners |
| `aria-*`, `data-*`, `role`, `tabIndex` и остальные HTML-атрибуты | Передаются на корневой элемент; семантику и доступное имя задаёт потребитель |
| `ref` | Внешний callback- или object-ref объединяется с `viewportRef` контекста и указывает на тот же `HTMLDivElement` |

`orientation`, `viewportPadding` и `scrollMode` задаются на родительском
`Carousel`, а не на `Viewport`. Родитель нормализует padding в CSS-строку,
учитывает его в границах прокрутки, а в `PAGE` вычитает осевые отступы из размера
области для группировки и центрирования страниц. Не подменяй эти отступы через
CSS: измерения родителя должны соответствовать оформлению области.

Корневой `<div>` имеет `width: 100%`, `height: 100%`, `box-sizing: border-box`
и `overflow: hidden`. Ограничь размер композиции; для вертикальной карусели
нужна ограниченная высота.

### Touch-жесты

- Используется первый элемент `targetTouches`. На `touchstart` запоминаются
  координаты и текущее смещение, переход ленты отключается, listeners
  `touchmove`, `touchend`, `touchcancel` устанавливаются на `window`.
- Основная ось — X для `HORIZONTAL`, Y для `VERTICAL`. Направление жеста
  выбирается, когда абсолютное смещение по любой оси стало **больше 5 px**:
  если поперечное больше основного, жест считается прокруткой страницы.
  При равенстве выигрывает ось карусели; выбор сохраняется до конца жеста.
- Поперечный жест не вызывает `preventDefault`, не обновляет положение ленты
  и не переключает слайды. До выбора оси текущая реализация уже двигает ленту
  и вызывает `preventDefault` для cancelable-событий; 5 px — порог выбора
  направления, а не порог начала drag.
- Вдоль оси cancelable `touchmove` получает `preventDefault`; listener
  зарегистрирован с `{ passive: false }`. Неканцелируемое событие обрабатывается
  без попытки отмены. Ориентация и границы читаются из актуальных refs родителя.
- Во время drag `transform` и `transition` ленты временно задаются напрямую.
  За начальной или конечной границей лишнее расстояние уменьшается втрое
  (rubber-band); это не зацикливание.
- На `touchend` основное смещение **больше 50 px** вызывает `prevSlide`,
  меньше `-50 px` — `nextSlide`. Ровно ±50 px и короткий жест не переключают
  карусель. Шаг и границы перехода определяет родитель в режиме `ITEM` / `PAGE`.
- `touchcancel` и поперечный жест не вызывают навигацию. На end/cancel
  listeners удаляются, временные `transform` / `transition` очищаются:
  управление возвращается CSS и состоянию родителя. Повторный start снимает
  предыдущие listeners перед регистрацией новых; unmount также снимает их.

## Дизайн-токены

У `Viewport` нет собственных цветовых дизайн-токенов; `tokens` пуст.
Токены `Carousel.Button_*` в общем `styles/Carousel.module.less` оформляют
кнопки навигации, а не область просмотра.

`--triplex-next-runtime-carousel-viewport-padding` — внутренняя runtime-переменная
с нормализованным `viewportPadding` родителя. Это не дизайн-токен, её не нужно
добавлять в `ThemeProvider` или генерируемые файлы тем. Значение из контекста
имеет приоритет над одноимённым свойством в `style` потребителя.

## Инварианты

- Сохраняются `forwardRef`, корневой `<div>`, ref-target `HTMLDivElement`,
  `displayName="Carousel.Viewport"`, класс `viewPort` и публичный
  `ICarouselViewportProps`. Объединение внешнего ref с ref контекста обязательно
  для измерений родителя; при размонтировании оба получают `null`.
- `Viewport` не хранит индекс или постоянное смещение и не рассчитывает страницы:
  это ответственность ближайшего `Carousel`. Контекст содержит один ref области
  и один ref ленты; несколько областей в одном родителе не поддерживаются.
- Runtime-padding берётся из контекста и применяется после пользовательского
  `style`. Имена runtime-переменной и существующие barrel-экспорты сохраняются.
- Порог выбора оси 5 px, строгий порог перехода 50 px, направление переходов
  и сопротивление на границах сохраняются без отдельного согласования поведения.
- Глобальные listeners принадлежат текущему жесту и удаляются при end, cancel,
  повторном start и размонтировании. `touchmove` остаётся непассивным.
- Зависимости touch callbacks включают используемые refs контекста; в родительском
  `Carousel` эти refs стабильны. Код остаётся совместимым с React 17.

## Accessibility

- Область — обычный `<div>` без встроенной роли, `tabIndex`, ARIA-текста
  или клавиатурной обработки. Для имени композиции при необходимости задай
  `role="region"` и `aria-label` родителю; язык выбирает потребитель.
- Горизонтальная область использует `touch-action: pan-y`, вертикальная —
  `pan-x`. Поперечная прокрутка страницы сохраняется после выбора направления
  жеста; touch не заменяет доступную клавиатурную навигацию.
- Для клавиатуры предусмотрены `Carousel.PrevButton` / `Carousel.NextButton`
  и, в `PAGE`, `Carousel.Indicators`. На устройствах `(pointer: coarse)`
  кнопки навигации не рендерятся. Доступные имена кнопок и индикаторов
  передаёт потребитель.
- `overflow: hidden` не исключает невидимые слайды из accessibility-дерева
  и Tab-порядка. `aria-hidden` / `inert`, связи слайдов с индикаторами,
  управление фокусом и объявления смены слайда автоматически не создаются.
- При `prefers-reduced-motion: reduce` CSS-переход ленты отключается в общем
  LESS; перемещение пальцем остаётся непосредственным.

## Связанные компоненты

- [Carousel](Carousel-ai.md) — родитель, владелец геометрии, состояния и
  навигации; публично предоставляет область как `.Viewport`.
- `Carousel.Track` — вложенный `<div role="presentation">`, располагает
  слайды и применяет постоянное смещение из контекста. Во время жеста
  `Viewport` временно управляет его inline `transform` / `transition`.
- `Carousel.Item` — слайд с последовательным `index`, регистрируется
  для измерений родителя; размещается внутри ленты.
- `Carousel.PrevButton` / `Carousel.NextButton` — кнопки перехода, обычно
  размещаются внутри области, поверх ленты.
- `Carousel.Indicators` — навигация по страницам `PAGE`; размещается
  рядом с областью просмотра.
