# create-task

Превращает короткое описание («надо добавить Badge тему DANGER») в корректно
оформленную задачу Linear, пригодную как готовое ТЗ для агента.

## Воркфлоу

### 1. Собери вход

Из сообщения пользователя: компонент(ы), тип работы, суть. Если критичное
непонятно — задай вопросы одним раундом, не растягивай.

### 2. Сверься с репозиторием

Прежде чем писать описание:

- существует ли компонент (`src/components/{Name}/`), его текущий API;
- состояние в `docs/ai/ROADMAP.md`;
- есть ли `{Name}-ai.md`, stories, тесты.

Acceptance criteria должны опираться на реальное состояние кода.

### 3. Проверь дубликаты

Поиск похожих открытых задач в команде TRI (`list_issues` по названию
компонента). Если есть похожая — покажи пользователю, спроси: дополнить её
или создавать новую.

### 4. Черновик

```text
Title: {Component}: краткое описание (≤70 символов)

## Контекст
{зачем, текущее состояние}

## Что сделать
{конкретные шаги}

## Acceptance criteria
- [ ] {проверяемый пункт}
- [ ] tsc / vitest / eslint проходят
- [ ] release notes обновлены (если меняется публичное поведение)

## Ссылки
- src/components/{Name}/
- docs/ai/ROADMAP.md {если релевантно}

Labels: component:{Name}, type:{refactor|stories|docs|ai-ready|feature|bug}
Project: {AI-Ready Phase 1 — если задача из ROADMAP}
Priority: {если пользователь указал}
```

Покажи черновик, жди подтверждения.

### 5. Создай

`save_issue` (без `id` — создание) в команду TRI. Если нужного label ещё нет — создай
(`component:*`, `type:*`). Верни пользователю ID и URL задачи.
Предложи сразу взять в работу: `/take-task TRI-XXX`.

## Жёсткие ограничения

- Не создавай задачу без подтверждения черновика.
- Один запуск = одна задача (для пачки — `/sync-roadmap` или явный список от пользователя).
- Не выноси в задачу секреты/внутренние URL — трекер может быть доступен шире репозитория.
