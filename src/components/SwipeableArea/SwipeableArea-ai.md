# SwipeableArea

## Назначение

Контейнер карточки с реализацией горизонтального свайпа: движение пальца
сдвигает контент и открывает боковую область с действиями. Свайп влево
открывает `rightSwipeableArea`, свайп вправо — `leftSwipeableArea`.

Собственного оформления у компонента нет — только позиционирование боковых
областей, transition сдвига и блокировки скролла и кликов на время жеста. Фон,
отступы и содержимое карточки приходят снаружи (обычно `ListItemContent`).

Используй когда: на мобильной ширине нужно спрятать действия карточки под
свайп — так устроены элементы списков (`ListItem`, `ListTableItem`).

Не используй когда: действия должны быть доступны без тач-жеста. Свайп
воспроизводится только пальцем: ни мышь, ни клавиатура его не выполняют,
а компонент не даёт визуального триггера для открытия области. Для готового
табличного элемента списка со свайпом бери `ListTableItem` — он сам собирает
`SwipeableArea` и `ListItemControls`.

## Варианты и props

`ISwipeableAreaProps` расширяет `React.HTMLAttributes<HTMLDivElement>` —
`...rest` уходит на корневой `<div>`.

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `children` | `React.ReactNode` | Контент карточки. Лежит поверх боковых областей и сдвигается при свайпе |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `leftSwipeableArea` | `React.ReactNode` | — | Контент, открывающийся свайпом **вправо**. Если не передан, свайп вправо ничего не двигает |
| `rightSwipeableArea` | `React.ReactNode` | — | Контент, открывающийся свайпом **влево**. Если не передан, свайп влево ничего не двигает |
| `onSwipeLeft` | `() => void` | — | Открылась `rightSwipeableArea`. Вызывается только на открытии и только если свайп длиннее порога |
| `onSwipeRight` | `() => void` | — | Открылась `leftSwipeableArea`. Те же условия |
| `className` | `string` | — | Мерджится с собственным классом через `clsx` |

Закрывающий свайп (когда область уже открыта) колбэки **не** вызывает — они
сообщают только о факте открытия.

### Императивный ref — `ISwipeableAreaRef`

`ref` компонента — не DOM-элемент, а объект с методами. Единственный способ
подвинуть контент без тач-жеста.

| Метод | Что делает |
|---|---|
| `swipeLeft()` | Открывает `rightSwipeableArea` |
| `swipeRight()` | Открывает `leftSwipeableArea` |
| `closeSwipe()` | Закрывает открытую область |

Метод молча ничего не делает, если соответствующая область не отрисована.
Колбэки `onSwipeLeft` / `onSwipeRight` при вызове методов **не** срабатывают.

### Как обрабатывается жест

| Фаза | Поведение |
|---|---|
| `touchstart` на контенте | Запоминаются координаты пальца и текущий сдвиг контента; на документ вешается разовый слушатель `touchend` |
| Первое `touchmove` | Определяется тип жеста: `abs(deltaY) > abs(deltaX)` — это скролл, контент до конца жеста не двигается; иначе — свайп |
| Последующие `touchmove` | Контент едет за пальцем, но не дальше ширины открываемой области; на время свайпа у контента `touch-action: none` |
| `touchend` (на документе) | Если длина свайпа больше `SWIPE_MIN_DISTANCE` (24px) — область открывается или закрывается, иначе контент возвращается в положение, с которого начинался жест |
| `touchstart` вне компонента | Открытая область закрывается |

Мультитач (`event.touches.length !== 1`) игнорируется при перемещении: на
старте координаты запоминаются всегда, но контент не поедет, пока в жесте
не останется ровно один палец.

Прозрачность боковой области считается как `|сдвиг| / ширина области`, поэтому
она проявляется по мере свайпа. Ширина берётся из `getBoundingClientRect()` в
момент жеста — область с нулевой шириной открыться не сможет.

Логика жеста вынесена в чистые функции `resolveSwipeMove` и `resolveSwipeEnd`
(`src/components/SwipeableArea/utils.ts`) и покрыта unit-тестами. Компонент
хранит только состояние: сдвиг контента, тип жеста и флаг анимации.

### Известные ограничения

Оба пункта существуют с первой версии компонента и не менялись при
AI-рефакторинге — при правках их стоит держать в голове.

- **Сдвиг контента не сбрасывается, если боковая область перестала
  передаваться.** Открыли `leftSwipeableArea`, затем перестали передавать этот
  prop — область размонтируется, а контент останется сдвинутым, оставив пустую
  полосу внутри `overflow: hidden`. Закрыть можно через `closeSwipe()`.
- **Боковая область нулевой ширины даёт невалидный `opacity`.** Прозрачность
  считается делением на ширину области, поэтому у пустой области
  (`leftSwipeableArea={null}`) получается `NaN`, и React ругается на невалидное
  значение CSS-свойства. Визуально это ни на что не влияет: пустой области не
  видно.

## Дизайн-токены

Токенов нет. `SwipeableArea.module.less` содержит только позиционирование,
`transition` сдвига и `touch-action`. Цвета и фон приходят от контента —
например, `ListItem.Background` у `ListItemContent`.

## Инварианты

- **`forwardRef` на компоненте — не убирать.** Ref типизирован
  `ISwipeableAreaRef` и наполняется через `useImperativeHandle`: получить через
  него корневой `<div>` нельзя, и менять это — breaking change для
  `ListTableItem` и потребителей библиотеки.
- **Публичные экспорты barrel** (`src/components/SwipeableArea/index.ts`):
  `SwipeableArea`, `ISwipeableAreaProps`, `ISwipeableAreaRef`. Переименование —
  breaking change. `utils.ts` — внутренний модуль, в barrel не попадает.
- **`displayName = "SwipeableArea"`.**
- **Корневой DOM — `<div>`.** На него уходят `className`, `...rest` и `data-tx`;
  тег не настраивается.
- **Порог свайпа `SWIPE_MIN_DISTANCE = 24` — внутренняя константа.** Пропа для
  него нет; изменение значения меняет ощущение жеста у всех потребителей.
- **Боковые области рендерятся, только если соответствующий prop передан**
  (`!== undefined`), и остаются в DOM всё время жизни компонента. Скрытость
  закрытой области — следствие `opacity` и перекрытия контентом, а не
  размонтирования.
- **`touch-action: pan-y` на контенте и `touch-action: none` во время
  горизонтального свайпа** — без этого браузер уводит жест в скролл страницы.
- **`::after` поверх контента при открытой области** — гасит нажатия на
  вложенные элементы карточки, пока область открыта. Убрать — значит разрешить
  случайные клики по карточке при открытых кнопках.
- **Слушатели документа снимаются при размонтировании** (`touchstart` — всегда,
  `touchend` — если компонент размонтирован в середине жеста).
- **React 17-совместимость.** Компонент уходит в ветку `release-0`; React
  18-only API (`useId`, `useSyncExternalStore`, `useInsertionEffect`)
  использовать нельзя.

## Accessibility

Собственных ARIA-атрибутов компонент не выставляет и текстов не хардкодит —
библиотека мультиязычная, а содержимое боковых областей приходит снаружи.

Что важно знать потребителю:

- **Клавиатурного эквивалента свайпа нет.** Компонент слушает только `touch`-
  события. Если действия из боковой области критичны, продублируй их доступным
  элементом или открывай область через `ISwipeableAreaRef`.
- **Кнопки боковых областей фокусируются по Tab и в закрытом состоянии** —
  области всегда в DOM, а `opacity: 0` фокус не забирает. Это осознанный
  компромисс текущей реализации: если такой обход недопустим, скрывай
  содержимое области на своей стороне.
- **Открытая область не помечается для скринридера.** `::after` блокирует
  только указатель; порядок чтения и фокус остаются прежними.

## Связанные компоненты

- `ListTableItem` (`src/components/List`) — единственный потребитель внутри
  библиотеки, который опирается на императивный контракт: он всегда оборачивает
  свой контент в `SwipeableArea`, прокидывает наружу `swipeableAreaRef` типа
  `React.Ref<ISwipeableAreaRef>` и подключает `controlButtons` как
  `rightSwipeableArea`. Любая правка `ISwipeableAreaRef` должна сверяться с ним.
- `ListItemControls`, `ListItemControlsButton`, `ListItemControlsButtonDropdown`
  (`src/components/List`) — стандартное наполнение боковой области: контейнер
  кнопок действий и сами кнопки.
- `ListItemTailLeft` / `ListItemTailRight` (`src/components/List`) —
  декоративные «хвосты», подсказывающие, что карточку можно свайпнуть.
  Размещаются внутри `SwipeableArea` рядом с контентом.
- `ListItem` / `ListItemContent` (`src/components/List`) — типичное окружение:
  `ListItem` даёт элемент списка, `ListItemContent` — фон и отступы карточки,
  без которых боковые области просвечивали бы сквозь контент.
