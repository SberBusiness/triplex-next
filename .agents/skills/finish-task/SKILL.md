# finish-task

Финализация задачи Linear после того, как изменения закоммичены.

## Предусловия

- Доступен Linear MCP (иначе — сообщи и остановись).
- В ветке есть коммиты задачи. Если есть незакоммиченные изменения —
  сначала предложи `/commit-component`.

## Воркфлоу

### 1. Определи задачу

Извлеки ID из имени ветки: `(TRI|TRIPLEX)-\d+`.

- `TRI-XXX` — задача в Linear, продолжай.
- `TRIPLEX-XXX` (legacy) — задачи в Linear может не быть; поищи по ID
  в заголовках, если нет — сообщи пользователю и заверши без действий в трекере.

### 2. Собери факты

- `git log main..HEAD --oneline` — коммиты задачи.
- `git diff main --stat` — затронутые файлы/компоненты.
- Обновлялись ли release notes (`stories/release-notes/v1/*.mdx` в diff).
- Вердикт `change-reviewer`, если он запускался в этой сессии.

### 3. Push и PR

- Если ветка не запушена — спроси разрешение на `git push -u origin <ветка>`.
  **Без явного подтверждения не пушь** (см. `docs/ai/commits.md`).
- PR создаёт пользователь. По явной просьбе — `gh pr create` с заголовком
  `TRI-XXX Краткое описание`.

### 4. Комментарий в задачу

`create_comment` в задачу TRI-XXX:

```markdown
## Резюме работы

**Сделано:** {1–3 предложения}
**Компоненты:** {список}
**Проверки:** tsc ✅/❌ · vitest ✅/❌ · eslint ✅/❌ · ревью: {вердикт change-reviewer / не запускался}
**Release notes:** обновлены / не требуются
**PR:** {ссылка, если есть}
```

Покажи черновик комментария пользователю перед отправкой.

### 5. Статус

- Проверь через `get_issue`, привязался ли PR (GitHub-интеграция Linear
  линкует по `TRI-XXX` в имени ветки и двигает статусы сама:
  PR открыт → In Review, смержен → Done).
- Если PR не привязался или интеграции нет — предложи вручную перевести
  задачу в In Review (статус типа `started`/review — найди через
  `list_issue_statuses`).

## Жёсткие ограничения

- Не переводи задачу в Done вручную — Done наступает после мержа PR.
- Не пушь и не создавай PR без явного подтверждения.
- Не отправляй комментарий без показа черновика.
