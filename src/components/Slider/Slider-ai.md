# Slider

## Назначение

Слайдер с одним ползунком — готовая сборка `SliderExtended`: полоса, ползунок, трек и метки
уже собраны, потребителю остаётся задать диапазон, шаг, метки и владеть значением.

Используй когда: пользователь выбирает одно число из диапазона и точность ввода не важна —
сумма, срок, процент, громкость.

Не используй когда:

- Нужен выбор диапазона двумя ползунками — возьми `SliderRange`.
- Нужен нестандартный состав частей (без меток, без трека, своё содержимое ползунка) или
  собственная разметка подсказки — собери слайдер из `SliderExtended`.
- Нужно ввести точное число — слайдер не заменяет `NumberField` / `AmountField`; при крупных
  диапазонах их обычно ставят рядом со слайдером.
- Ползунку нужна текстовая подпись для скринридера — `Slider` её передать не позволяет
  (см. Accessibility), собирай из `SliderExtended`.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `min` | `number` | Минимальное значение диапазона |
| `max` | `number` | Максимальное значение диапазона |
| `size` | `EComponentSize.MD \| EComponentSize.LG` | Размер. `SM` не поддерживается |
| `value` | `number` | Текущее значение ползунка |
| `onChange` | `(value: number) => void` | Вызывается со значением шага, на который переместился ползунок |
| `marks` | `ISliderMark[]` | Метки под полосой: `{ value: number; label: React.ReactNode }` |

### Опциональные props

| Prop | Тип | По умолчанию | Описание |
|---|---|---|---|
| `step` | `number \| number[]` | `1` | Длина шага либо массив значений шагов. В массиве первое значение равно `min`, последнее — `max` |
| `reverse` | `boolean` | `false` | Значения возрастают справа налево |
| `disabled` | `boolean` | `false` | Слайдер не активен: части не реагируют на курсор и выпадают из табуляции |
| `renderTooltipContent` | `(value: number) => React.ReactNode` | — | Содержимое подсказки над ползунком. Без этого prop подсказка не рендерится вовсе |

Остальные атрибуты `React.HTMLAttributes<HTMLDivElement>` (включая `className`, `id`,
`aria-*`, `data-*`) уходят на **корневой `div`** слайдера. `children` запрещён
(`children?: never`): разметку собирает сам компонент.

### Особенности поведения

- **Значение контролируемое.** Компонент не хранит значение: он рисует позицию по `value` и
  сообщает новое значение через `onChange`. Без обновления `value` снаружи ползунок не
  двигается — включая `disabled`-слайдер, где источник правды тем более остаётся у
  потребителя.
- **`step` числом строит шаги как `[...range(min, max, step), max]`.** Последний шаг всегда
  равен `max`, даже если он не кратен шагу: при `min: 0, max: 10, step: 3` шаги равны
  `0, 3, 6, 9, 10`.
- **`step` массивом задаёт произвольную шкалу.** Шаги равны визуально, а не по значению —
  так делается шкала сумм с укрупняющимся шагом (см. story `Amounts`). Массив, собранный
  инлайн в JSX, пересчитывает шаги на каждом рендере потребителя; вынеси его в константу.
- **Пустой массив шагов (`step: []`) не рендерит ничего** — `SliderExtended` возвращает `null`.
- **Значение вне диапазона не отбрасывается, а зажимается** при расчёте позиции: ползунок
  встаёт на край. В `onChange` при этом уходят только значения из массива шагов.
- **Клик по полосе и по метке двигает ползунок** на ближайший шаг / на значение метки.
- **`marks` не обязаны совпадать с шагами.** Метка со значением вне `[min, max]` прижимается
  к краю полосы; `value` метки используется как React-ключ, поэтому дубли значений дадут
  предупреждение о неуникальных ключах. Подпись рендерится через `Text` (`B3` для `LG`,
  `B4` для `MD`).
- **Подсказка видна только при `:hover` и `:focus` ползунка** — управляется стилями, не
  props. Постоянно видимой подсказки нет, поэтому текущее значение обычно дублируют рядом со
  слайдером (так сделано во всех stories).
- **Ширину и внешние отступы задаёт потребитель.** Своей ширины у слайдера нет; собственные
  вертикальные отступы (под ползунок и под метки) он добавляет сам.

## Дизайн-токены

Собственных токенов у компонента нет: своих стилей `Slider` не имеет и целиком состоит из
`SliderExtended`. Внешний вид настраивается токенами группы `Slider` — их список и порядок
переопределения см. в `SliderExtended-ai.md` → «Дизайн-токены». Значения по умолчанию —

## Инварианты

- **`Slider` — единственный компонент семейства без `forwardRef`:** объявлен как `React.FC`,
  `ref` не принимает и никуда не пробрасывает. Это расхождение с codestyle библиотеки
  зафиксировано как есть — добавление `forwardRef` меняет наблюдаемый контракт (сейчас React
  предупреждает о `ref` на функциональном компоненте, после — ref начнёт указывать на
  корневой `div`), поэтому делается только отдельным согласованным изменением с записью в
  release notes. У `SliderExtended` и всех его частей `forwardRef` есть — не убирать.
- **`ISliderProps` наследуется от `ISliderExtendedProps` и `ISliderExtendedDotProps`**
  (`Omit<..., "onChange" | "step">` + `Pick<..., "onChange" | "value">`). Переименование
  props в `SliderExtended` ломает публичный API `Slider` — менять только вместе.
- **Порядок частей в разметке (`Rail` → `Dot` → `Track` → `Marks`) и наличие `Rail`
  обязательны.** Позиции клика и перетаскивания считаются от DOM-узла полосы; без `Rail`
  работает только клавиатура. `Tooltip` обязан лежать внутри `Dot`.
- **`renderTooltipContent` вызывается на каждом рендере** с текущим `value` — держи её
  дешёвой и без side effects.
- **`children?: never`** — часть публичного API: состав слайдера фиксирован, расширяется он
  только через `SliderExtended`.
- Реализация остаётся React 17-совместимой (без `useId`, `useSyncExternalStore` и прочих
  React 18-only API): код синхронизируется в `release-0`.

## Accessibility

- **Ползунок — `role="slider"`** с `aria-valuemin`, `aria-valuenow`, `aria-valuemax` из
  `min` / `value` / `max` (рендерится `SliderExtended.Dot`).
- **Подпись ползунку `Slider` передать нельзя.** Все лишние props уходят на корневой `div`,
  а не на ползунок, поэтому `aria-label` / `aria-labelledby` окажутся на контейнере без роли.
  Если подпись или `aria-valuetext` (нелинейная шкала, суммы, единицы измерения) обязательны —
  собирай слайдер из `SliderExtended` и передавай атрибуты прямо в `SliderExtended.Dot`.
- **Клавиатура:** `ArrowLeft` / `ArrowDown` — шаг назад, `ArrowRight` / `ArrowUp` — шаг
  вперёд. Обработчики вызывают `preventDefault`, чтобы страница не скроллилась.
  `Home` / `End` / `PageUp` / `PageDown` не поддерживаются.
- **Трек в табуляцию не попадает:** перетаскивание трека клавиатурой имеет смысл только для
  двух ползунков, а у `Slider` он один.
- **Метки кликабельны, но не фокусируются** и не читаются как элементы управления: это
  ускоритель для мыши, дублирующий клавиатурное перемещение по шагам.
- **Подсказка не связана с ползунком через `aria`** — она показывается по `:hover`/`:focus`
  и для скринридера бесполезна; значение доступно через `aria-valuenow`.
- **`disabled` только визуальный и мышиный.** Части получают `pointer-events: none` и
  `tabIndex -1`, но нативного `disabled` у `span` нет: программно установленный фокус
  оставляет клавиатурное перемещение работающим. Источником правды остаётся `value`
  потребителя.

## Связанные компоненты

- `SliderExtended` (`src/components/SliderExtended/`) — составной слайдер, из которого
  собран `Slider`. Нужен, когда состава `Slider` не хватает: свой набор частей, своя
  подсказка, `aria`-атрибуты на ползунке.
- `SliderRange` (`src/components/SliderRange/`) — тот же слайдер на два ползунка: принимает
  `values` парой, следит за их порядком и прокидывает `draggableTrack`.
