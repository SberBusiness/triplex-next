# CarouselItem

## Назначение

Слайд составного `Carousel`: оборачивает содержимое в `<div>` и регистрирует
его DOM-узел по `index` в контексте карусели. Родитель использует регистрацию
для измерения слайдов, расчёта страниц и границ прокрутки.

Используй внутри `Carousel.Track`, вложенного в `Carousel.Viewport`, когда
элемент должен участвовать в навигации карусели. Размер, оформление и
интерактивность содержимого задаёт потребитель.

Не используй как самостоятельную карточку или контейнер списка: вне композиции
`Carousel` слайд не получает измерений и навигации родителя.

Публичный путь — статическое поле `Carousel.Item`. Импортируй `Carousel` из
`@sberbusiness/triplex-next`; именованного экспорта `CarouselItem` из пакета нет.
Интерфейс `ICarouselItemProps` экспортируется публично.

```tsx
import { Carousel } from "@sberbusiness/triplex-next";

const items = [
    { id: "first", title: "Первое предложение" },
    { id: "second", title: "Второе предложение" },
];

<Carousel style={{ width: 320, height: 180 }}>
    <Carousel.Viewport>
        <Carousel.Track>
            {items.map((item, index) => (
                <Carousel.Item
                    key={item.id}
                    index={index}
                    aria-label={item.title}
                    style={{ width: 280, height: 180 }}
                >
                    {item.title}
                </Carousel.Item>
            ))}
        </Carousel.Track>
    </Carousel.Viewport>
</Carousel>
```

## Варианты и props

### Обязательный prop

| Prop | Назначение и ограничения |
|---|---|
| `index` | Позиция слайда с нуля. Индексы должны быть уникальными, непрерывными и соответствовать DOM-порядку: `0, 1, 2, …`. Это ключ регистрации для геометрии, а не идентификатор данных и не HTML-атрибут |

### Содержимое и HTML-атрибуты

| Prop | Назначение и ограничения |
|---|---|
| `children` | Произвольное содержимое слайда; собственных требований к его типу или интерактивности нет |
| `className`, `style`, `aria-*`, `data-*` и остальные атрибуты `<div>` | Передаются на корневой слайд. `className` объединяется с внутренним классом `slide`, а `style` позволяет задать размеры и оформление |
| `ref` | Указывает на корневой `HTMLDivElement` слайда; поддерживаются объектный и callback ref |

У компонента нет собственного активного или disabled-состояния и отдельных
вариантов по ориентации. Раскладку и направление задаёт `Carousel.Track`
через настройки родителя.

### Индексы и динамический список

- Вычисляй `index` из позиции при `map`, а React `key` — из стабильного
  идентификатора данных. После удаления, вставки или перестановки пересчитай
  индексы оставшихся элементов, сохраняя их ключи.
- Геометрия родителя обходит диапазон `0..count-1`. Пропуск индекса, дубликат
  или индекс, не совпадающий с порядком узлов, нарушает расчёт размеров и страниц;
  компонент не проверяет и не исправляет такой ввод.
- При получении DOM-узла слайд записывает его в реестр. При смене `index`
  прежняя регистрация удаляется, при размонтировании запись очищается.
- Регистрация не запускает самостоятельный пересчёт геометрии. За измерения
  отвечают родитель и его `ResizeObserver`, наблюдающий `Viewport` и `Track`.
- Слайд не задаёт ширину или высоту. Для горизонтальной карусели важна его
  измеримая ширина, для вертикальной — высота; размеры могут определяться
  содержимым либо стилями потребителя.

## Дизайн-токены

Собственных дизайн-токенов нет: класс `.slide` задаёт flex-раскладку,
центрирование содержимого и `flex-shrink: 0`. Поэтому `tokens` в frontmatter
пуст. Оформление вложенных карточек принадлежит их компонентам.

Токены `Carousel.Button_*` в общем `Carousel.module.less` относятся к кнопкам
навигации. Runtime-переменные геометрии ленты и области просмотра не являются
токенами `CarouselItem`.

## Инварианты

- `forwardRef` сохраняется; ref указывает на внешний `<div>` слайда, а не на
  его содержимое, `Track` или `Viewport`. Внешний ref объединяется с
  регистрационным callback без потери любого из них.
- `Carousel.Item`, `ICarouselItemProps`, обязательный числовой `index` и
  существующие barrel-экспорты сохраняют имена и типы.
- `displayName` — `"Carousel.Item"`, внутренний CSS-класс — `slide`.
- Регистрация принадлежит ближайшему `CarouselContext`. Смена индекса и
  размонтирование очищают прежнюю запись; нельзя оставлять устаревшие узлы
  в карте измеряемых слайдов.
- Последовательность индексов совпадает с DOM-порядком. Родитель рассчитывает
  количество элементов по числу зарегистрированных узлов, а не по `children`.
- По умолчанию корень имеет `role="group"`. Остальные атрибуты передаются
  через spread после роли, поэтому потребитель может явно переопределить её.
- Компонент остаётся совместимым с React 17; новые React 18-only API не нужны.

## Accessibility

- Значение роли по умолчанию — `group`; доступное имя при необходимости задаёт
  потребитель через `aria-label` или `aria-labelledby`.
- Слайд не является кнопкой, вкладкой или пунктом списка. Для действий внутри
  него используй семантические интерактивные элементы.
- `index` не создаёт доступного номера, `aria-posinset`, `aria-setsize` или
  связей с индикаторами. Подписи и необходимые ID-связки задаёт потребитель.
- У самого слайда нет обработчиков клавиатуры или переноса фокуса. Он не
  получает `tabIndex`, `aria-hidden` либо `inert` автоматически: содержимое
  за границей видимой области остаётся в accessibility-дереве и Tab-порядке.
  Доступность такого содержимого нужно учитывать в продуктовой композиции.

## Связанные компоненты

- `Carousel` — родитель, владелец контекста, геометрии, текущего положения и
  навигации. `Carousel.Item` доступен через его статическое поле.
- `Carousel.Track` — flex-лента слайдов; задаёт расстояние между ними и смещение
  по выбранной оси. У самого слайда нет отдельного prop `gap`.
- `Carousel.Viewport` — ограничивает видимую область через `overflow: hidden`
  и обрабатывает touch-жесты; слайды размещаются в ленте внутри этой области.
