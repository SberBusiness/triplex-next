# sync-roadmap

Двусторонняя сверка ROADMAP ↔ Linear. Источник правды о состоянии кода —
`docs/ai/ROADMAP.md` в репозитории; Linear — рабочий трекер поверх него.

## Воркфлоу

### 1. Прочитай ROADMAP

`docs/ai/ROADMAP.md`, таблица покрытия Phase 1: компонент + колонки
(AI.md / Storybook examples / AI refactoring). Раздели компоненты:

- **готовые** — все колонки ✅;
- **в работе / не начатые** — есть ⬜.

### 2. Прочитай Linear

- Найди проект «AI-Ready Phase 1» (`list_projects`). Если его нет —
  предложи создать (после подтверждения — `save_project`).
- `list_issues` проекта, включая закрытые.
- Задачи компонентов ищи по заголовку `{Component}: AI-Ready`.

### 3. Сравни

| Ситуация | Действие |
|---|---|
| Компонент не готов, задачи нет | Кандидат на создание задачи |
| Задача Done, но в ROADMAP есть ⬜ | Расхождение — в отчёт |
| Задача открыта, но в ROADMAP всё ✅ | Расхождение — в отчёт (вероятно, задачу можно закрыть) |
| Компонент не готов, задача открыта | Норма, пропусти |

### 4. Покажи отчёт и подтверди

Таблица: кандидаты на создание + расхождения. **Жди подтверждения** —
пользователь может исключить компоненты из списка.

### 5. Создай задачи батчем

Для каждого подтверждённого компонента — `save_issue` (без `id` — создание):

- Title: `{Component}: AI-Ready (Phase 1)`
- Описание: текущее состояние колонок ROADMAP, что осталось сделать,
  acceptance criteria = недостающие колонки ✅ + проверки проходят.
- Labels: `component:{Name}`, `type:ai-ready`. Project: «AI-Ready Phase 1».

### 6. Итог

Сколько создано, список расхождений, что рекомендуется сделать руками
(закрыть устаревшие задачи, обновить ROADMAP и т.п.).

## Жёсткие ограничения

- Ничего не создаёт и не меняет в Linear без подтверждения из шага 4.
- Не правит `docs/ai/ROADMAP.md` — галочки ставят агенты по факту работы над кодом.
- Не закрывает задачи в Linear автоматически — только рекомендует.
