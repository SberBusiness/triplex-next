# MobileView

## Назначение

Сервисный headless-компонент адаптивности. Рендерит `children`, когда ширина окна
браузера соответствует мобильному устройству (`max-width: 767px`), и `fallback` —
во всех остальных случаях. Собственной разметки не добавляет: в DOM попадает
ровно тот элемент, который выбран по медиа-запросу.

Реализован как сокращение над `MediaWidth` с `maxWidth={EScreenWidth.SM_MAX}` —
вся логика подписки на медиа-запрос живёт в `MediaMaxWidth` → `useMatchMedia`.

Используй когда: на мобильной ширине нужно отрендерить **другое дерево**
компонентов, а не просто другие стили — мобильный вариант дропдауна вместо
десктопного, тултип-модалка вместо всплывающей подсказки, список вместо таблицы.

Не используй когда:
- Разница между мобильным и десктопом чисто визуальная (отступы, шрифт,
  раскладка) — это дешевле и надёжнее решается медиа-запросом в
  `*.module.less`, без перемонтирования поддерева.
- Нужен не выбор между двумя готовыми элементами, а булево значение для props
  или условной разметки вокруг — используй хук `useMobileView` (см. ниже).
- Нужна не мобильная, а произвольная граница ширины — используй `MediaWidth`
  (`minWidth` / `maxWidth`) напрямую.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `children` | `React.ReactElement \| null` | Элемент для мобильной ширины (`<768px`). `null` — на мобильной ширине не рендерится ничего |
| `fallback` | `React.ReactElement \| null` | Элемент для остальных ширин. Обязателен: prop без значения по умолчанию, для «ничего» передаётся явный `null` |

Опциональных props нет. `className`, `...rest` и `ref` компонент не принимает —
у него нет собственного host-элемента.

### Особенности поведения

- Граница — `EScreenWidth.SM_MAX` (`767px`), запрос `(max-width: 767px)`. При
  ширине ровно `767px` рендерится `children`, при `768px` — `fallback`.
- **Ветки взаимоисключающие.** При пересечении границы одна ветка размонтируется,
  вторая монтируется: локальный state, фокус, значения неконтролируемых полей и
  текущие анимации внутри поддерева теряются. Состояние, которое должно
  переживать смену ширины, храни выше `MobileView` (или передавай его как props
  в обе ветки).
- Значение медиа-запроса читается синхронно на первом рендере (`useMatchMedia`
  вызывает `window.matchMedia` в инициализаторе `useState`), поэтому «мигания»
  десктопной ветки на мобильном экране нет.
- Пересчёт при ресайзе идёт по событию `change` у `MediaQueryList`, а не по
  `resize` окна — слушатель снимается при размонтировании.
- **Компонент не SSR-safe:** `window.matchMedia` вызывается на первом рендере.
  Это поведение унаследовано от `useMatchMedia` и общее для всего семейства
  `MediaWidth`.

### `useMobileView`

Хук из того же barrel (`src/components/MobileView/useMobileView.ts`). Возвращает
`boolean` — результат того же медиа-запроса `(max-width: 767px)`. Нужен, когда
от ширины зависят props или разметка вокруг, а не выбор между двумя готовыми
элементами: размер кнопки, `block`-режим, наличие иконки. Так его используют
`DateFieldTarget`, `MonthYearFieldTarget`, `CheckboxTreeExtended`, `IslandWidget`,
`IslandAccordionItem`, `Tooltip`.

Компонент и хук строят строку запроса независимо (`MediaMaxWidth` — из своего
prop, хук — из константы `MOBILE_QUERY`), но обе строки собираются из
`EScreenWidth.SM_MAX` и всегда совпадают. Правя одно, проверь второе.

## Инварианты

- **Без `forwardRef` — осознанное исключение** из общего правила библиотеки:
  компонент не рендерит собственный host-элемент, форвардить `ref` некуда.
  Не добавлять и не убирать без отдельного решения — это публичный контракт.
- **Имена и типы props `children`, `fallback`** и интерфейс `IMobileViewProps`
  (экспортируется из barrel) — публичное API, не менять. `fallback` остаётся
  обязательным: сделать его опциональным можно только осознанно, это меняет
  контракт у потребителей.
- **Сигнатура `useMobileView(): boolean`** и его barrel-экспорт — публичное API.
  Хук используется внутри библиотеки в шести компонентах.
- **Граница мобильной ширины — `EScreenWidth.SM_MAX`.** Не хардкодить `767px`
  и не переводить на `MD_MIN` с `min-width`: значение согласовано с сеткой
  дизайн-системы и с LESS-переменными брейкпоинтов.
- **Делегирование в `MediaWidth`** — не инлайнить `useMatchMedia` в
  `MobileView.tsx`: семейство `MediaWidth` остаётся единственным местом с
  логикой подписки на медиа-запросы.
- Реализация остаётся React 17-совместимой (без `useId`,
  `useSyncExternalStore` и прочих React 18-only API): код синхронизируется
  в `release-0`.

## Accessibility

- Собственной ARIA-семантики нет — компонент прозрачен для accessibility-дерева.
- Невыбранная ветка **не рендерится в DOM**, а не скрывается визуально: скринридер
  и последовательность табуляции видят только актуальный вариант. Дублирования
  контента для ассистивных технологий не возникает, но и «десктопная» разметка
  на мобильном недоступна.
- Смена ветки при ресайзе удаляет из DOM сфокусированный элемент — фокус
  переходит на `<body>`. Если это критично (открытый оверлей, форма), верни
  фокус явно на стороне потребителя.
- Медиа-запрос завязан на ширину окна, а не на тип ввода: на десктопе с узким
  окном тоже рендерится мобильная ветка. Не завязывай на `MobileView` наличие
  touch-специфичных обработчиков как единственного способа взаимодействия.

## Связанные компоненты

- `MediaWidth` (`src/components/MediaWidth/`) — общий случай: `minWidth` и/или
  `maxWidth`. `MobileView` — его частный случай для мобильной границы.
- `MediaMaxWidth`, `MediaMinWidth`, `MediaBetweenWidth` — реализации конкретных
  диапазонов, к которым `MediaWidth` делегирует рендер.
- `useMatchMedia` (`src/components/MediaWidth/useMatchMedia.ts`) — хук подписки
  на произвольный медиа-запрос, основа и компонента, и `useMobileView`.

### Потребители внутри библиотеки

Компонентом (`MobileView`): `Dropdown`, `Tooltip` (`TooltipBody`, `TooltipLink`),
`HelpBox`, `DateField`, `SuggestField`, `TabsLine`, `ImageGallery`,
`ImageGalleryExtendedMain`.
Хуком (`useMobileView`): `DateFieldTarget`, `MonthYearFieldTarget`,
`CheckboxTreeExtended`, `IslandWidget`, `IslandAccordionItem`, `Tooltip`.

В unit-тестах потребителей мобильная/десктопная ветка задаётся подменой
`window.matchMedia` (как в `Dropdown.test.tsx`) либо мокированием самого модуля
`MobileView` (как в `ImageGallery.test.tsx`, `LightBox.test.tsx`).

## Stories

Основные истории: `stories/MobileView/MobileView.stories.tsx`
Файлы примеров: `stories/MobileView/examples/`

Playground у компонента нет: `children` и `fallback` — React-элементы, для
Controls в них нечего настраивать. Скриншот-тесты снимают обе ветки: на
viewport `xs` (575px) рендерится мобильный вариант, на `xl` (1200px) —
`fallback`.

| Story | Example file | Что демонстрирует |
|---|---|---|
| `Default` | `Default.tsx` | Выбор между `children` и `fallback` по ширине окна |

(`stories/MediaWidth/examples/MobileViewExample.tsx`) — он показывает связь
частного случая с общим и остаётся в документации `MediaWidth`.
