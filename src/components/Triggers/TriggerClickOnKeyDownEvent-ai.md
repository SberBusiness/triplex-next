# TriggerClickOnKeyDownEvent

## Назначение

Сервисный headless-компонент. Пока смонтирован, слушает `keydown` на `window`
(через `KeyDownListener`) и при совпадении кода нажатой клавиши с `eventKeyCode`
вызывает нативный `click()` на кнопке из `targetRef`. Собственной разметки не
рендерит: `children` выводятся как есть.

Используй когда: действие уже реализовано кнопкой, и его нужно продублировать
глобальной горячей клавишей — закрытие оверлея по `Esc`, листание галереи
стрелками. Клик по настоящей кнопке даёт потребителю один обработчик вместо двух
и сохраняет поведение кнопки (`disabled`, `onClick`, аналитика).

Не используй когда:
- Нужно выполнить произвольный обработчик, а не клик по кнопке — бери
  `KeyDownListener` напрямую.
- Нужно несколько разных клавиш с разными действиями — `ComposedKeyDownListener`.
- Клавиша должна работать только внутри конкретного элемента — навесь `onKeyDown`
  на сам элемент: слушатель здесь глобальный и сработает при вводе в любое поле
  на странице.

## Варианты и props

### Обязательные props

| Prop | Тип | Описание |
|---|---|---|
| `eventKeyCode` | `number \| number[]` | Код клавиши из `EVENT_KEY_CODES` или массив кодов. Тип переиспользуется из `IKeyDownListenerProps` через `Pick` |
| `targetRef` | `React.RefObject<HTMLButtonElement>` | Ссылка на кнопку, по которой выполняется клик. Кнопка не обязана находиться внутри `children` |
| `children` | `React.ReactElement` | Рендерится как есть. Обязателен по типу (в отличие от `KeyDownListener`), обёртки над ним компонент не создаёт |

### Особенности поведения

- **Клик выполняется только по видимой кнопке.** Перед `click()` проверяется
  `buttonEl.offsetParent !== null` — у элемента, скрытого через `display: none`
  (своим стилем или стилем предка), `offsetParent` равен `null`. На этом
  построены `LightBoxClose` и `LightBoxArrow`: десктопная и мобильная копии
  кнопки переключаются через `display: none`, оба триггера смонтированы, но
  срабатывает только видимый.
- **Проверка не покрывает другие способы скрытия.** `visibility: hidden`,
  `opacity: 0`, нулевой размер и вынос за пределы вьюпорта дают ненулевой
  `offsetParent`, и клик пройдёт. Отдельный случай — `position: fixed`: у таких
  элементов `offsetParent` тоже `null`, поэтому кнопка во `fixed`-контейнере
  клавишей не кликается.
- **Пустой `targetRef` безопасен.** Если `targetRef.current === null` (кнопка не
  смонтирована), обработчик молча ничего не делает.
- **Клик синтезируется через нативный `HTMLElement.click()`**, а не через
  `dispatchEvent` с кастомным событием: `onClick` кнопки получает обычное
  `click`-событие с `event.detail === 0`. `disabled`-кнопка такой клик нативно
  игнорирует.
- Триггеры **вкладываются друг в друга**, когда одна клавиша должна обслуживать
  несколько кнопок (`LightBoxClose`, `LightBoxArrow`): каждый уровень добавляет
  свой `KeyDownListener` и не влияет на `children`.
- Компонент не вызывает `preventDefault` и не останавливает всплытие — нажатие
  клавиши дойдёт и до других слушателей.

## Инварианты

- **`forwardRef` осознанно отсутствует** — то же исключение, что у
  `KeyDownListener`: компонент не рендерит собственный host-элемент, форвардить
  `ref` некуда. Добавление `forwardRef` изменило бы публичный тип компонента с
  `React.FC` на `React.ForwardRefExoticComponent` — не делать.
- **`ITriggerClickOnKeyDownEventProps` не экспортируется** (ни из файла, ни из
  barrel) — это осознанное состояние публичной поверхности. Экспорт интерфейса
  расширяет публичное API и делается только отдельной задачей.
- **Имена props `children`, `eventKeyCode`, `targetRef`** и barrel-экспорт
  `TriggerClickOnKeyDownEvent` из `src/components/Triggers/index.ts` — публичное
  API, не менять.
- **Тип `targetRef` — `RefObject<HTMLButtonElement>`**, а не `Ref`: компоненту
  нужен доступ к `.current`, callback-ref сюда не подходит.
- **Проверка `offsetParent !== null`** — часть контракта, а не оптимизация. Её
  снятие сломает `LightBoxClose`/`LightBoxArrow`: клавиша начнёт кликать скрытые
  копии кнопок. Тест `does not click the target button when it is hidden`
  фиксирует это поведение.
- Реализация остаётся React 17-совместимой (без хуков-новинок React 18): код
  синхронизируется в ветку `release-0`.

## Accessibility

- Собственной ARIA-семантики нет — компонент прозрачен для accessibility-дерева.
- Горячая клавиша глобальная и не анонсируется screen reader'ом, но действие
  всегда доступно и обычным путём — через саму кнопку. Это и есть причина
  кликать по кнопке, а не вызывать обработчик напрямую.
- `Esc` для закрытия оверлеев — ожидаемое поведение. Возврат фокуса на триггер
  после закрытия компонент не делает: это ответственность потребителя
  (`ModalWindow`, `LightBox`).
- Если кнопка иконочная, доступное имя (`title` / `aria-label`) передаёт
  потребитель — библиотека мультиязычная и текст внутри не хардкодит.

## Связанные компоненты

- `KeyDownListener` (`src/components/KeyDownListener/`) — слушатель клавиш, на
  котором построен триггер. Нужен, когда по клавише выполняется произвольный
  обработчик, а не клик по кнопке.
- `ComposedKeyDownListener` — несколько клавиш с разными обработчиками; альтернатива,
  когда действий по клавишам больше одного и они не сводятся к клику по кнопке.
- `LightBox` — потребитель, который опирается на проверку видимости: `LightBoxClose`
  и `LightBoxArrow` держат смонтированными по два триггера на одну клавишу
  (десктопная и мобильная копии кнопки) и рассчитывают, что сработает только
  видимая.

### Остальные потребители внутри библиотеки

- `ModalWindowClose` — закрытие модального окна по `Esc`.
- `Confirm.Close` — закрытие подтверждения по `Esc` при `clickByEsc`.
- `LightBoxSideOverlayCloseDesktop` — закрытие бокового оверлея лайтбокса по `Esc`.
